# Search master 전수 감사 결과

감사일: 2026-07-24

범위: 원본 JSON → Bareun A1 CSV → `05_search_master` 전량

방식: 입력을 수정하지 않는 세션별 스트리밍 대조
기계 판독 보고서: `search_master_audit_20260724.json`

## 결론

현재 전량 search master는 **Bareun A1을 search master로 옮기는 과정에서는
완전하다.** 17,156세션·5,103,356행의 ID, 행 순서, `form`, `tagged`가 모두
일치하고 중복·누락 세션이 없다.

그러나 연구용 최종 정본으로 부르기 전에 다음 네 보완이 필요하다.

1. 2026-07-24에 복구한 2023년 네 세션의 메타데이터 1,090행 반영
2. lexicon 사전 발음 예외 층의 실제 배선과 출처 열 추가
3. WAV·어절 TextGrid·격리 여부 coverage 열 계산
4. Bareun token과 원문 어절 수가 다른 508,153행의 용도·매핑 정책 명시

따라서 “CSV 전량 생성”은 완료됐지만 “모든 연구 인프라 열이 보완된 최종 CSV”는
아니다. 기존 전량본은 삭제하거나 덮어쓰지 않고 비교 기준선으로 보존한다.

## 2. 5,103,358 대 5,103,356의 원인

현재 기계 산출물은 일관되게 **5,103,356**을 지시한다.

- Bareun A1 전수 재계산: 5,103,356
- search master 전수 재계산: 5,103,356
- `D:\10_LAYERS\03_freq_dictionaries\_partials\meta_2024.txt`: 728,257
- `D:\10_LAYERS\_merge_rerun.txt`: 합계 5,103,356
- 2026-07-23 search master build log: 5,103,356

과거 서술 문서는 2024를 728,259로 적어 합계를 5,103,358로 만들었다. 현재
파일·중간 메타·병합 로그 어디에서도 그 두 행을 확인할 수 없다. 따라서 이는
search master 변환 중 두 행이 소실된 것이 아니라 **과거 서술 수치의 2024년
2행 오기**로 판정한다.

## 3. 원본 JSON과 Bareun A1의 차이

원본 JSON의 5,157,997 utterance 중 54,641행은 `form`이 빈 값이다.
`bareun_dialogue_full.py`의 `iter_utterances()`는 `form.strip()`이 비어 있으면
분석 대상에서 제외하므로 A1에는 5,103,356행이 들어간다.

| 연도 | `form` 빈 utterance | JSON 대비 |
|---:|---:|---:|
| 2020 | 238 | 0.0273% |
| 2021 | 42,296 | 2.9866% |
| 2022 | 11,798 | 1.3435% |
| 2023 | 232 | 0.0342% |
| 2024 | 24 | 0.0033% |
| 2025 | 53 | 0.0090% |
| **합계** | **54,641** | **1.0593%** |

- 54,641행 전부 `form`이 비어 있다.
- 이 중 44,440행은 `original_form`은 비어 있지 않다.
- 10,201행은 `form`과 `original_form`이 모두 비어 있다.
- 제외는 4,386세션에 걸쳐 있고 특히 2021·2022에 집중된다.

이것은 search master의 후속 누락이 아니라 A1의 명시적 입력 정책이다. 형태소·
표기 환경 후보 검색은 정규화된 `form`이 있는 5,103,356행을 대상으로 할 수
있다. 다만 `original_form`만 있는 44,440행이 비언어 표지인지, 복구 가능한
언어 자료인지 표본 분류한 뒤 Methods에 제외 기준을 명시해야 한다.

## 4. 2023년 메타데이터 네 세션

수정된 `file_meta.csv`는 네 세션을 올바르게 포함하지만, 전량 search master는
수정 전에 생성됐다.

| 세션 | 행 | `category_norm=미상` | `topic=미상` |
|---|---:|---:|---:|
| SDRW2300000445 | 216 | 216 | 216 |
| SDRW2300000457 | 196 | 196 | 196 |
| SDRW2300000473 | 295 | 295 | 295 |
| SDRW2300001337 | 383 | 383 | 383 |
| **합계** | **1,090** | **1,090** | **1,090** |

새 builder로 격리 생성한 `SDRW2300000445` 216행에서는 메타 결측이 0이므로
수정 로직은 검증됐다. 최종 스키마가 정해진 뒤 네 세션 또는 해당 연도를
archive 후 재생성한다.

## 5. lexicon 예외 발음

lexicon v1 전수 실측:

- 총 1,296,777행
- `pron_1`: 613,441행
- `pron_2`: 41,237행
- `pron_g2p`: 683,336행
- `pron_1` 우선, 없으면 `pron_g2p` 폴백 시 발음 가용: 1,296,777행
- `morph_dict`: 820,776행

현재 코드 상태:

- `predict_pron.py`에 `(word, pos_tag)` lexicon 색인·조회 헬퍼는 있다.
- `build_search_master.py`는 `lexicon_full`을 열지 않는다.
- builder가 색인을 만들거나 `predict_pron()`에 전달하지 않는다.
- 전량 CSV에 사전 발음 또는 그 출처를 표시하는 열이 없다.

즉 사전 파일과 준비 헬퍼는 있지만 **현재 전량 예측발음에는 사전 예외 발음이
반영되지 않았다.** 사전 발음은 음향에서 추정한 실제 발음이 아니라 표준/등재
발음 기준선이다. `pron_1`, 복수 인정형 `pron_2`, `pron_g2p` 폴백과 규칙 기반
예측을 비파괴 별도 열로 보존해야 한다.

## 6. coverage 열

현재 전량본의 다음 세 열은 5,103,356행 전부 빈 문자열이다.

- `has_wav`
- `has_tg_eojeol`
- `quarantined`

7/24에 강화한 builder는 이를 `미계산`으로 명시해 빈 값을 실제 결측으로
오해하지 않게 했지만, 실제 존재 여부 계산은 아직 구현되지 않았다. 후보 CSV에서
음성·TextGrid를 모으는 연구 흐름상 이 세 열은 구현 가치가 높다.

## 7. form 어절과 Bareun token의 불일치

기존 build log의 `align_warn`:

| 연도 | 경고 행 | 해당 연도 A1 대비 |
|---:|---:|---:|
| 2020 | 122,337 | 14.055% |
| 2021 | 137,315 | 9.994% |
| 2022 | 72,117 | 8.324% |
| 2023 | 51,051 | 7.538% |
| 2024 | 69,880 | 9.596% |
| 2025 | 55,453 | 9.445% |
| **합계** | **508,153** | **9.957%** |

대표 원인은 Bareun token 경계가 원문 공백과 다르게 합쳐지거나 갈라지는 것이다.
예: 원문 한 어절을 여러 token으로 분석하거나, 원문의 보조용언 띄어쓰기를 한
token으로 합친다.

이 경고는 두 작업에 미치는 영향이 다르다.

- 발화 단위 후보 추출: `tagged`에서 형태소 포함 여부, `form`에서 표기 환경을
  각각 찾으므로 계속 가능하다.
- 형태소 후보를 정확한 TextGrid `words` 어절 번호에 자동 연결: 경고 행에서는
  1:1 대응을 가정하면 안 된다.

Bareun 응답의 `Token.text`에는 `content`, `begin_offset`, `length`가 있지만
현재 A1 CSV는 형태소열만 저장하고 이 span을 버렸다. 이후 재분석 또는 경고행
보완 시 token span을 반드시 저장해야 한다. 당장은 경고행을 숨기지 않고 후보
manifest에 남기며, 연구자는 해당 발화의 전체 음성과 TextGrid를 검토한다.

권고 순서:

1. 이 전수 감사 결과를 정본 문서에 반영한다.
2. lexicon 발음과 coverage의 스키마를 비파괴 열로 확정한다.
3. 2020의 작은 층화 표본으로 새 CSV를 만들고 기존 전량본과 비교한다.
4. 통과하면 2020 한 연도만 archive→재생성→전수 검증한다.
