2. PV-A 설계 — 현재 자산만 초안 · 검토 대상

2.1 현상별 20건 배분표 (부족 칸은 인접 칸 재배분, 결과는 manifest 기록)

현상 (PV 코드)형태소 내부어절 내 경계어절 간비고
① 경음화 (PT)677ㅎ·ㄶ·ㅀ 종성 제외(격음화 환경) — 관찰 후 확정
② ㄴ앞 비음화 (NAN)488ㅁ 앞 포함 여부는 관찰 메모
③ ㄹ앞 비음화 (NAL)884한자어 단일어(격려류)가 내부형 핵심
④ ㄴ삽입 (NI)—1010동결 후보 94만 행에서 추출, RC1 curated 1건 포함 시도
⑤ ㄴㄹ·ㄹㄴ (LLN)884내부 ㄴㄹ(신라류) 6 · ㄹㄴ 2
⑥ 모음조화 (VH)—16—아계 8 · 어계 8 + 축약 보조 4
⑦ 모음충돌 (HIA)—12—비축약 12 + 축약 보조 8

2.2 draft query — 비동결·PV 전용

  • 기존 선언형 builder(build_db_v1_target_manifest.py) 무수정 재사용. config만 pv_preview_*_20260819.json으로 신규.
  • query_id에 PV_ 접두, query_role=preview_environment_sweep, 자체 SHA는 기록하되 동결 아님 명시.
  • 조건 골격(전부 draft): PT = 장애음 종성 + 평음 초성 / NAN = +ㄴ / NAL = +ㄹ / LLN = ㄴ+ㄹ, ㄹ+ㄴ / VH = V어간 + E어미 + ㅇ초성 {ㅏ,ㅓ} / HIA = VH에서 어간 종성 빈값 / VH·HIA 축약 보조 = 철자 어절이 (봐|봤|와|왔|줘|줬|해|했|돼|됐)$ — Bareun 축약 분절 실측(P0) 겸용.
  • 선두 편중 방지: 연도당 상한을 넉넉히(예: 200) 뽑고 표본기가 결정적 간격(stride)으로 할당량까지 축소하는 2단 추출.

2.3 D1-lite 내부형 표본기

morph_units를 연도별 스트리밍해 같은 형태소 안 인접 음절쌍(좌 coda·우 onset 일치)을 상한까지만 수집. 읽기 전용·조기 중단. 구현 전 필수 morph_units 실제 헤더 실측(열 이름 추정 금지).

2.4 대화 문맥 manifest (±2 발화, 파일 간 보존)

입력: utterance_master_v2(실측 확인 열: dialogue_id, session_id, utt_seq, start/end/dur, speaker_id, co_speaker_ids …) + RC0 ledger 자산 상태. target ±2 발화를 행으로 보존하고, 다른 파일의 발화도 삭제 없이 상태만 표시(wav_status / textgrid_status / same_file_as_target).

2.5 bundle·미리듣기·검토기

  • 번호순 flat 폴더: NNN__현상__연도__utt_id/ — target.wav · context_pm2.wav(±2 stitched, 역환산 manifest 필수) · 6-tier 사본(읽기 전용) · row.csv(근거)
  • INDEX.html 검토기: 오디오 + 문맥 텍스트(파일 간 상태 표시) + 환경 근거 + 관찰 메모(localStorage 저장 → JSONL 내보내기)
  • REVIEW.csv 병행 생성(Excel 폴백) — 도구 사용감 자체가 PV 관찰 항목

2.6 PV 기록 schema (탐색 전용 · append-only)

pv_id, phenomenon_code, pv_query_id, environment_scope, year, utt_id, occurrence_ref,
listened, env_impression(env_ok|env_wrong|unsure), realization_impression(자유 기술),
audio_quality_note, context_sufficient(yes|need_more_before|need_more_after|need_other_file),
missing_info_note(최종 schema에 필요한 정보 제안), schema_field_suggestion,
tool_note, reviewer, reviewed_at
