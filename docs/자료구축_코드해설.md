## 0. 큰 그림

원본 말뭉치(전사 JSON·음성)를 **층층이 주석을 얹어** 분석 가능한 레이어로
바꾸는 것이 A단계다. 데이터는 리포에 없고 전부 **D: 외장하드**에 있으며,
코드는 경로를 직접 쓰지 않고 [config/paths.json](../config/paths.json) 한 곳을
거친다.

```
[원본 JSON]  D:/00_RAW/dialogue_json  (17,156파일 · 발화 510만)
   │
   ├─A1─▶ 01_bareun_raw        형태소 분석 (바른)          ← 텍스트의 뼈대
   │        │
   │        ├─A2─▶ 02_sense_annotated   의미번호(우리말샘)  ← 내용어에 뜻 부여
   │        │
   │        ├─A3─▶ 03_freq_dictionaries 빈도사전 5종        ← "빈도 효과"의 재료
   │        ├─A4─▶ 04_metadata_index    사용역·주제·화자
   │        └─A5─▶ (03에 층화)          성별×연령×사용역 빈도
   │
[원본 PCM]  D:/20_AUDIO/00_source  (2025 59.6GB)
   └─음성─▶ 03_wav → (MFA 강제정렬) → 06_textgrid_merged  음소 시간정렬
   │
[다층위 말뭉치]  gold 레이어 수입 → 검증 규준
   │
   └─A6─▶ 검색 결과(utt_id) ↔ wav·TextGrid 연계
```

**설계 원칙 세 가지** (모든 스크립트가 공유):
1. **레이어 불변**: 뒷 단계는 앞 단계 출력을 **수정하지 않고** 새 폴더에 쌓는다
   (1차 바른 원본은 절대 안 건드림 → 언제든 재현·재부여 가능).
2. **체크포인트·재개**: 저사양 PC + USB 외장하드 → 밤샘 배치가 기본. 완료
   단위(파일/연도/세션)를 건너뛰어 중단 후 이어서 실행.
3. **근거를 남긴다**: 자동 부여에는 **방법(method)·신뢰도**를 같이 기록해,
   연구 시 신뢰 수준으로 필터링할 수 있게 한다.

## A1. 형태소 분석 — 텍스트의 뼈대

| | |
|---|---|
| **입력자료** | 원본 전사 JSON (발화별 `form`) |
| **코드** | 파일럿 [bareun_dialogue_pilot.py](../scripts/python/bareun_dialogue_pilot.py) → 본작업 [bareun_dialogue_full.py](../scripts/python/bareun_dialogue_full.py) |
| **왜** | 빈도·현상 분석의 기본 단위가 **형태소**다. 구형 분석기를 상용급 **바른(Bareun)**으로 전면 교체해 6개년을 **한 체계로 통일**(표준 태그, 어절 경계 보존). 먼저 120발화 파일럿으로 품질을 확인한 뒤 전량 실행 — "대량 작업 전 파일럿" 원칙. |
| **역할·산출물** | `D:/10_LAYERS/01_bareun_raw/{연도}/{파일ID}.csv` — 발화별 `utt_id, speaker_id, form, tagged, n_morphs`. `tagged`는 어절 사이 공백·어절 내 형태소 `+` 구분(예: `춥/VA+ㄴ/ETM`). 화자 메타(`_speakers.csv`)도 같이 저장. |
| **검증** | 17,156파일·`form` 비어 있지 않은 분석대상 **5,103,356발화**·형태소 토큰 5,096만. 원본 JSON 전체 5,157,997행 중 `form` 빈 54,641행은 입력 정책상 제외(7/24 전수 감사). 공식 다층위 대비 **형태소 F1 0.929**(A단계 검증). |

> 순수 바른 분석만 담는다(의미번호 없음). 의미는 A2가 별도 레이어로 얹는다 —
> 레이어 불변 원칙.

## A2. 의미번호 — 내용어에 "뜻" 부여

| | |
|---|---|
| **입력자료** | `01_bareun_raw` + 자체 어휘목록(lexicon v2, 우리말샘·표준대사전 매핑) + NIKL 어휘의미 말뭉치(LS, 구어 SXLS) |
| **코드** | 부여 [assign_sense_layer.py](../scripts/python/assign_sense_layer.py) → 보완 [supplement_sense_layer.py](../scripts/python/supplement_sense_layer.py) |
| **왜** | "의미 빈도" 효과를 보려면 형태소가 **어느 뜻으로 쓰였는지**가 필요. 다만 자동 의미부여는 오류 위험이 커서, **근거의 강도별로 등급**을 매긴다. |
| **역할·산출물** | `02_sense_annotated/{연도}/{ID}.csv` (형태소 long format). 부여 방법 5등급: ① `monosemous`(단의어 확정) ② `ls_sxls`(구어 말뭉치 최빈 sense + 우세비율) ③ `ls_all`(전체 분포) ④ `ambiguous`(후보만) ⑤ `not_found`. 조사·어미·기호는 대상 외(`not_target`). 보완 패스는 접사·어근을 lexicon에서 조회하고, 다의어는 첫 의미번호를 **잠정 부여**(`lex_first`, 신뢰도 공란 + 후보 전체 보존). |
| **검증** | 내용어 78%→보완 후 **90%** 부여. 공식 WSD 대비 **76.4%**(단의어는 100% — 우리말샘 체계 변동 없음). |

> 핵심 아이디어: **틀릴 수 있는 부여일수록 그 사실을 데이터에 남긴다**
> (method·confidence·candidates). 연구자가 "확정된 것만" 골라 쓸 수 있다.

## A3. 빈도사전 — "빈도 효과"의 재료

빈도사전은 이 연구의 **종속·독립 변수 창고**다. 세 스크립트가 층위별로 만든다.

### A3a. 형태소·어절 빈도

| | |
|---|---|
| **입력자료** | `01_bareun_raw` 전량 + 외부 규준(MP 형태분석·LS 어휘의미) + lexicon v2(로마자) |
| **코드** | [build_freq_dictionaries.py](../scripts/python/build_freq_dictionaries.py) |
| **왜** | 우리 말뭉치 자체 빈도만으로는 대표성을 논하기 어려움 → **외부 규준(MP/LS/KoFREN)과 나란히** 두고, 음운 분석을 위해 **로마자·IPA**까지 붙인다. 저사양 RAM 대비 **연도별 count → merge** 2단계. |
| **역할·산출물** | `03_freq_dictionaries/morpheme_freq_dictionary.csv`(형태소+태그), `eojeol_freq_dictionary.csv`(표면형), 로마자→IPA 변환표(`_roman_mfa_to_ipa.csv`, 수동 수정 가능). |

### A3b. 의미별 빈도

| | |
|---|---|
| **입력자료** | `02_sense_annotated`(A2 보완 완료본) + LS 의미별 빈도 |
| **코드** | [build_sense_freq.py](../scripts/python/build_sense_freq.py) |
| **왜** | 같은 형태소라도 **뜻마다 빈도가 다르다** → 의미빈도 효과 검증용. |
| **역할·산출물** | `sense_freq_dictionary.csv` — (형태소,태그,의미번호) 단위 빈도 + 부여방법 + LS 비교. **A2 보완 후 실행**해야 정확. |

### A3c. 외부 규준 통합

빈도사전 각 항목에 **MP/LS/KoFREN + (뒤에) ML2025** 비교 컬럼, 어원(고유어/한자어/외래어), IPA가 붙어 규준 5종 체제를 이룬다.

**산출 규모**: 형태소 165,920항 · 어절 857,443항.

## 음성 파이프라인 — 소리에 시간을 붙이기 (2025년 신규분)

목표: 발화 음성을 **음소 단위로 시간정렬한 TextGrid**를 만드는 것(음운 실현
판정·운율 분석의 토대). 2020–2024는 1기에 완료, 여기서는 **2025년분**을 같은
방식으로 붙여 6개년을 완비한다.

| 순서 | 코드 | 입력 → 출력 | 역할 |
|---|---|---|---|
| ① 해제 | [extract_2025_pcm.py](../scripts/python/extract_2025_pcm.py) | PCM zip(59.6GB) → 원본 PCM | 압축 해제(재개 가능) |
| ② 변환 | [pcm_to_wav_2025.py](../scripts/python/pcm_to_wav_2025.py) | PCM → `03_wav/individual/2025/*.wav` | 16kHz mono 16-bit WAV 587,174개 |
| ③ 텍스트 | [make_labs_2025.py](../scripts/archive/pre_2021_legacy_20260803/python/make_labs_2025.py) | 바른 `tagged` → `.lab` | 구 최초 구축 방식; 현재 어절 기준 생산에는 재사용하지 않음 |
| ④ 정렬 | (MFA, conda env `mfa`, korean_mfa v3.0) | wav+lab → 정렬 DB | 강제정렬(외부 도구) |
| ⑤ TextGrid | [merge_textgrid_v2.py](../scripts/python/merge_textgrid_v2.py) | 정렬 DB → 표준 3-tier TextGrid | **MFA export 교착을 우회** — DB에서 직접 생성 |

**왜 ③에서 바른 형태소로 발음열을 만드나**: 정렬 단위를 형태소 분석과
일치시켜 words tier가 A1 레이어와 맞물리게 하기 위해. **왜 ⑤에서 자체
생성하나**: MFA 기본 export가 이 규모에서 교착(sqlite 잠금·멈춤)을 일으켜,
정렬 결과 DB를 직접 읽어 [구 표준 tier v2](archive/decisions_pre_production/STANDARD_textgrid_tiers.md)를
안정적으로 뽑기 위함.

**산출**: 2025 표준 TextGrid 585,889개(정렬 커버리지 99.79%).
