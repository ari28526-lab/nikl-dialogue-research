# MORPH_R·형태소 위치 스키마 음운론적 시험

- 일자: 2026-07-31
- 대상: `tagged_roman.v2`, `morph_tokens`, `morph_units`,
  `morph_boundaries`, `orth_components`
- 질문: `[MORPH_R]`와 구조화 표가 다양한 한국어 표기·음운 환경을
  검색하는 인프라로 충분한가
- 판정: **보조 표시·기초 검색은 적합, 정밀 환경 검색은 구조화 표 필수**

## 1. 해석 범위

이 시험은 철자·형태소 환경을 잃지 않고 후보를 찾을 수 있는지를 본다.
MFA phone, 실제 음성 실현, ㄴ 삽입 여부, 경음화·연음의 실제 발생을
자동 판정하는 시험이 아니다. 그런 판단은 후보 WAV와 TextGrid를 연구자가
확인하는 실제 연구 단계에 남긴다.

시험 과정에서 종성에 올 수 없는 독립 자모 `ㄸ·ㅃ·ㅉ`가 기존 종성
로마자표에 없어 실패하는 사각지대를 발견했다. 독립 ㄴ·ㄹ 등의 기존 소문자
표기는 유지하고, 종성표에 없는 자음만 onset 로마자로 fallback하도록
교정했다. 이는 actual pilot 값은 바꾸지 않지만 전수 빌드의 예기치 않은
중단을 예방한다.

정밀 환경 후보를 뽑아서는 안 된다.

## 4. 연구 검색에서의 사용 구분

`[MORPH_R]`로 적합한 일:

- Praat에서 목표 형태소의 철자 로마자와 POS를 빠르게 확인
- 한 발화 안에서 음절·형태소·어절의 대략적 계층을 읽기
- 구조화 검색으로 뽑은 후보가 의도한 표기인지 교차 확인

`[MORPH_R]`만으로 하면 안 되는 일:

- `lk`를 실제 두 phone으로 해석
- 표기에 없는 실제 연음·중화·경음화·ㄴ 삽입을 판정
- 무음 초성 ㅇ을 빈 로마자만 보고 검색
- 형태소 첫·가운데·끝이나 경계 좌우 환경을 정규식으로만 판정

정밀 후보는 예를 들어 `morph_boundaries`에서 좌측 종성, 우측
`onset_zero`, 우측 중성, 양쪽 POS와 `boundary_scope`를 함께 조건으로
검색한다. 이후 WAV·TextGrid를 모아 실제 실현은 연구자가 판정한다.

## 5. 1번 검토행에 대한 결론

`[MORPH_R] H O k _ S I/MAG | YO _ J EU m/NNG`는 현재 목적, 즉
TextGrid 안의 보조 검색과 후보 확인에는 충분히 명료하다. 따라서
`MORPH_R_검색_가능=정상`으로 판정할 수 있다. 이 판정은
`[MORPH_R]`가 정밀 검색 정본이라는 뜻이 아니며, 그 정본은 구조화 표다.

전수 전에는 연도별 입력에서 지원하지 않는 자모·parse error·reserved
literal·최대 label 길이를 집계하는 preflight를 유지한다.
