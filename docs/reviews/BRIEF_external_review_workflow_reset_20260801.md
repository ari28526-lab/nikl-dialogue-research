# 외부 리뷰 브리프: 검수 교착 해소와 workflow 구조 리셋

- 작성일: 2026-08-01 KST
- 리뷰 성격: 코드 스타일 리뷰가 아닌 프로젝트 workflow·증거·진행성 감사
- 현재 계산 상태: 2020 `morph_search.v3` 1/23 성공 후 정지, 신규 r2 MFA 미시작

## 사용자가 느끼는 핵심 문제

1. 파일럿과 검수는 여러 번 했는데 실제 전수 생산은 계속 시작되지 않는다.
2. 반영됐다고 생각한 결정이 실제 runner·출력 schema·다음 단계 gate에는 반영되지
   않았을 가능성이 있다.
3. 기계적으로 검사할 수 있는 항목까지 연구자가 반복 확인했을 수 있다.
4. 과거 기준과 최신 기준이 같은 문서 구조에 쌓여 현재 정본과 역사 기록의 경계가
   흐려졌다.
5. 오류를 막기 위한 gate가 너무 많아져, 위험을 줄이는 대신 진도를 막는 gate가
   생겼을 수 있다.

리뷰의 목적은 안전장치를 없애는 것이 아니다. 각 검수가 실제로 막는 실패와 실패
뒤 행동을 명시하고, 의미가 중복되는 검수는 하나의 기계 gate로 통합하며, 언어학적
판단이나 자료 제외 승인처럼 사람만 결정할 수 있는 것만 연구자에게 남기는 것이다.

## 연구의 정본 목적

```text
형태소·표기상 음운형태 환경을 CSV/Parquet에서 검색
  → utt_id로 WAV·TextGrid·메타데이터를 수집
  → 선별 후보에만 KOINA·이어붙이기·wav2vec2 보조 분석
  → 연구자가 음성과 TextGrid를 보고 실제 실현 여부 판정
```

MFA/G2P phone은 자동 강제정렬 보조값이고 실제 실현 판정이 아니다. 원자료,
형태소 분석, 사전/규칙 발음, MFA phone, 보조 모델, 연구자 판정은 출처가 다른
열·표·tier로 분리한다.

## 실제로 확인된 문서 구조 위험

- Markdown 104개
- `docs/decisions` 53개

- `PROJECT_CURRENT_STATE.md` 안에 최신 정지점, 과거 4-tier/파일럿 상태, 여러

  뜻하지 않지만 제목만 보면 혼동 가능
- 2020–2025 조합검색 runner와 MFA 연도 큐가 현재 별도이며 연결 gate 정책 미확정
- 우리말샘 1:N과 최종 joined search Parquet은 중요하지만 아직 최종 연결되지 않음

위 항목은 최종 판정이 아니라 외부 리뷰가 실제 파일·Git·manifest로 검증할
우선 후보다.

## 리뷰가 만들어야 할 네 가지 원장

### 1. 생산 단계 원장

원자료부터 실제 연구까지 각 단계의 입력, 출력, 실행 코드, manifest, 현재 상태,
완료 정의와 다음 단계를 한 표에 둔다. `문서에 완료라고 쓰임`과 `현재 방법 계약의
실물 manifest가 있음`을 구분한다.

### 2. 결정–반영 추적 원장

사용자 결정 또는 외부 리뷰 지적이 다음 전 계층에 실제 반영됐는지 추적한다.

```text
요청/결정 → 정본 문서 → config/schema → 생산 runner → 테스트 → 실제 artifact
```

어느 한 단계라도 없으면 `부분 반영` 또는 `미반영`이다.

### 3. 검수 가치 원장

각 검수에 다음 질문을 적용한다.

1. 어떤 구체적 실패를 막는가?
2. 이미 다른 manifest/test가 같은 사실을 검사하는가?
3. 방법 계약이 바뀌지 않았는데 반복하는가?
4. 결과에 따라 실제로 다른 행동을 하는가?
5. 사람이 판단해야 하는가, 기계적으로 완전 검사 가능한가?

판정은 `유지`, `통합`, `기계화`, `조건부`, `폐지` 중 하나로 한다.

### 4. 문서·산출물 수명주기 원장

파일을 다음으로 분류한다.

- `canonical_active`: 지금 실행과 판단의 정본
- `supporting_evidence`: 정본이 인용하는 현재 증거
- `historical_valid`: 당시에는 유효했으나 현재 생산 기준은 아님
- `superseded`: 더 최신 결정/코드로 대체됨
- `failed_diagnostic`: 시행착오·실패 원인 증거
- `generated_review_artifact`: 재생성 가능한 검토용 산출물
- `unknown_needs_owner`: 용도·정본 여부 불명

Git 기록이 있으므로 삭제를 기본으로 하지 않는다. 문서 이동은 `git mv`, 원래 경로,
새 경로, SHA-256, 대체 정본, 이동 사유가 있는 manifest 뒤에만 수행한다. D:/E:/H:
대형 산출물은 별도 inventory와 사용자 승인 없이 이동·삭제하지 않는다.

## 리셋 뒤 기대하는 구조

리뷰어는 아래 개념을 반드시 보존하되, 실제 폴더명과 이동 범위는 링크·코드 참조를
조사해 최소 변경안을 권고한다.

```text
하나의 START_HERE
하나의 짧은 CURRENT_STATE
하나의 실행 순서 RUNBOOK
활성 방법·schema 정본
현재 증거 index
외부 리뷰와 resolution
날짜별 historical/superseded/failed archive
```

53개 decision 문서를 무조건 물리적으로 전부 옮기는 것이 목표가 아니다. 정본 index와
상태 metadata만으로 충분하면 대규모 이동보다 안전한 쪽을 선택한다.

## 진행을 재개하기 위한 종료 조건

외부 리뷰 뒤 다음이 한 화면에서 답변돼야 한다.

1. 지금 실제로 완료된 것은 무엇인가?
2. 2020 신규 MFA 전에 남은 blocker는 정확히 무엇인가?
3. 사용자가 결정해야 하는 것은 무엇이며, 왜 기계가 결정할 수 없는가?
4. 다음에 실행할 명령 하나는 무엇인가?
5. 그 명령이 끝나면 어떤 manifest로 완료를 판정하는가?
6. 실패하면 어느 checkpoint에서 재개하는가?
7. 어떤 검수는 이제 다시 하지 않는가?
