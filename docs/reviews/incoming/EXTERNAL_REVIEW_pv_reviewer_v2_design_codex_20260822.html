1. 사용자가 정할 네 가지

전체 대화는 텍스트로 검색

전체 세션 오디오는 넣지 않고, 전사 행을 검색·선택한다. 대상과 ±2 문맥 오디오는 지금처럼 유지한다. 권고

발음은 “예상형”과 “참조형”으로 분리

둘 다 실제 들린 발음이나 자동 정답이 아니다. 출처·상태를 붙이고 연구자가 들린 형식을 따로 기록한다. 권고

원유권(2022)은 공통 방법론 패널에만 연결

이 논문은 일곱 개별 분절 현상을 직접 다루지 않으므로 후보별 긍정적 현상 근거로 표시하지 않는다. 권고

새 파생 출력 root 허용 여부

기존 통과 산출물의 SHA 의미를 보존하려면 outputs/pilots/pv_seven_phenomena_reviewer_v2_20260822/를 새로 만든다. 허용하지 않으면 work/의 비정본 사용성 파일럿만 만든다.

4. 새 분석 없이 쓸 수 있는 정보

실측 헤더에는 화자·대화·형태·발음 참고 열이 이미 있다. v2는 선택된 exact ID만 읽어 화면에 드러내면 된다.

항상 보일 것

  • 현상·우선순위·연도
  • 표적 어절과 형태소 경계
  • 대상/±2 문맥 오디오
  • 들린 형식·확신도·겹침·문맥

접어 둘 것

  • 같은 화자 연속 묶음·전체 대화 검색
  • 성별·연령·지역·관계·주제
  • 규칙 예상형·사전 참조형
  • 문헌·exact ID·SHA·query 정보
말차례 주의. 화면의 DTRN은 동일 화자 행을 연속으로 묶은 조작적 ID다. 실제 담화론적 말차례나 운율구 정답으로 표시하지 않는다.

6. 기록과 문헌 연결 규칙

  • 기존 v1 JSONL 15행을 가져와 그대로 보존하고, 새 revision만 append한다.
  • raw ledger 15행, latest view 14행, possible duplicate 1행을 별도로 회계한다.
  • relation=not_found는 긍정적 문헌 badge로 쓰지 않는다.
  • evidence_owner=cited_source는 `재인용·원문 미확인` 상태를 붙인다.
  • 원유권 본인의 말뭉치·말차례·운율 설명만 공통 방법론 패널에 둔다.
  • KOINA·우리말샘 의미번호는 각각 not_run·not_joined로 남기고 이번 구현에서 만들지 않는다.

7. 더 단순한 구현안

기존 파일은 수정하지 않는다. 기존 builder, 11.6MB HTML, receipt, 사용자 JSONL, 통과한 PV root를 모두 읽기 전용으로 두고 새 builder·감사기만 추가한다.
  1. 14 exact ID만 입력으로 고정한다.
  2. 기존 연도·표별 200,000행 상한을 유지하고 자동 확대하지 않는다.
  3. 전체 대화는 텍스트만 포함하고 기존 28개 WAV payload의 SHA를 재검증한다.
  4. 찾지 못한 정보도 표본을 삭제하지 않고 상태로 남긴다.
  5. 새 출력 root는 기존 통과 root와 분리한다.
이번에는 하지 않음: KOINA, MFA, wav2vec2, Praat 측정, 자동 실현 판정, 우리말샘 의미번호 결합, 새 후보 추출, 전체 대화 오디오 포함.

합격은 실현 판정이 아니라 ① 표적을 즉시 찾음 ② 긴 문맥을 찾음 ③ 메모가 사고를 도움 ④ 기존+새 revision을 모두 내보냄의 네 조건이다.

그 다음. 이 3개가 통과한 뒤 연도별 30개 작업을 시작한다. 실제 태깅 묶음은 예상 청취시간 합계 약 1시간을 상한으로 나누고, 연도·현상 쿼터와 zero-drop 상태를 batch manifest에 함께 보존한다.

상세 필드·감사 조건은 같은 이름의 Markdown 보고서에 기록했다. 이 HTML은 사용자가 빠르게 판단하기 위한 요약본이다.
