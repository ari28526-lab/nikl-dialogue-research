### 2.3 왜 “전체 화자 연속 구간”을 기본으로 펼치면 안 되는가

선택된 14개는 모두 서로 다른 14개 세션·대화에 속한다. 현재 manifest에 기록된

`PV0163`의 대상은 254개짜리 묶음의 6번째다. 이를 처음부터 전부 펼치면 다시
세로가 지나치게 길어진다.

따라서 기본은 대상±2이고, 다음 순서로 점진적으로 펼치는 것이 낫다.

1. 대상이 속한 `조작적 동일화자 연속 묶음`만 펼치기
2. 전체 대화 전사 검색 패널 열기
3. 검색 결과 행을 선택해 대상 주변으로 이동하기

여기서 묶음은 동일 `speaker_id`가 연속된 기존 행을 모은 `derived_turn_id`일
뿐이며, 담화론적 말차례나 운율구의 정답이 아니다.

## 6. 문헌 연결 규칙

원유권(2022) evidence v2의 40행은 다음 규칙으로 연결한다.

1. `relation=not_found` 1행은 “이 논문에 일곱 분절 현상의 직접 근거가 없음”을
   기록한 감사 행이다. 후보 화면의 긍정적 근거로 표시하지 않는다.
2. `evidence_owner=cited_source` 10행은 원 출전을 직접 확인하지 않은 재인용
   근거이므로 `재인용·원문 미확인` 배지를 붙이거나 기본 화면에서 제외한다.
3. 원유권 본인의 말뭉치·말차례·운율 설명은 공통 방법론 패널에서만 보인다.
4. 화자 수 2,033/2,063 불일치는 두 값을 함께 보존하며 자동 정정하지 않는다.
5. KOINA는 이 논문의 직접 대상이 아니므로 문헌 패널에서 KOINA 근거로 표시하지 않는다.

### 7.4 새 출력 위치

## 9. v2 마이크로 사용성 Gate

전체 14개를 다시 듣지 않고 다음 3개만 확인한다.

| 표본 | 선택 이유 | 확인할 기능 |
|---|---|---|
| `PV0001` PT·2020 | 뒤 문맥 필요, 28단위 화자 연속 묶음 | 표적 강조, 뒤 확장, 한 후보 화면 |
| `PV0163` NI·2025 | 형태소/비교 발음 요구, 254단위 묶음 | 형태소 카드, 긴 묶음 검색·접기 |
| `PV0177` HIA·2025 | 형태소 위치 불명확, 중복 revision | HIA bounded join, 입력 예시, 중복 보존 |

합격 기준은 “세 표본의 실현을 판정했다”가 아니다. 다음 네 질문에 사용자가
답할 수 있으면 된다.

1. 어디를 들어야 하는지 즉시 알 수 있는가?
2. 더 긴 맥락을 필요할 때 찾을 수 있는가?
3. 메모 필드가 연구자의 사고를 방해하지 않고 돕는가?
4. 다시 JSONL로 내보냈을 때 기존 기록과 새 revision이 모두 남는가?

이 Gate가 통과한 뒤에만 연도별 30개 작업을 시작한다. 향후 실제 태깅 묶음은
단순히 30개씩만 자르기보다 예상 청취 시간을 합산해 **약 1시간 상한**의 batch
manifest로 나누되, 연도·현상 쿼터와 zero-drop 상태를 함께 보존하는 안을 권고한다.

## 11. 사용자가 확정할 네 항목

1. 전체 대화는 텍스트 검색만 제공하고 전체 오디오는 넣지 않는 안
2. 발음 정보는 `규칙 예상형`·`사전 참조형`으로만 표시하는 안
3. 원유권(2022)은 공통 방법론 패널에만 연결하는 안
4. 기존 통과 root를 보존하기 위해 새 sibling derivative root를 허용하는 안

1–3은 권고안 그대로 승인해도 된다. 4를 승인하지 않으면 v2는 `work/`의
비정본 사용성 파일럿으로만 만든다.
