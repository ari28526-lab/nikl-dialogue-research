# DB 조회 묶기·반복 계산 캐시의 제한된 비교

2026-10-17 사용자 요청으로 진행 중인 보강을 유지하고 완료 소스 2개, 783발화·5,337형태소에서 별도 시험했다. 원래 생산 코드·계약·장부를 수정하거나 전체 작업자를 추가하지 않았다. 기존 방식과 시험 방식의 반환 객체 전체 및 정렬된 JSON 바이트의 SHA-256이 모두 일치했다. 후보·기계 선택·보류·판단 근거·출현 대응 정보를 포함해 비교했다.

## 측정 조건

처음의 탐색 측정에서는 첫 파일 읽기의 비용이 섞여 캐시가 유리해 보였다. 이 결과를 채택하지 않고 파일을 먼저 예열한 뒤 다시 측정했다. 각 표본·구간에 예열 1회, 방식별 3회를 순서를 바꾸어 실행하고 중앙값을 비교했다. 기존 구현 자체의 조회 캐시는 측정 회차마다 별도 시험 프로세스 안에서만 초기화했다. 전체 시간과 프로세스 CPU 시간도 함께 남겼다.

DB 비교는 동일한 근거를 하나씩 조회하는 방식과 최대 300키 단위의 매개변수 조회를 비교했다. 기존 입력·영수증·소스 payload·후보 query 대응 검사를 유지했다. 캐시 비교는 세종 규칙 재적용 구간에서 (1) 기존 방식, (2) 근거 확인 계산만 캐시, (3) 판정 결과와 근거 확인을 모두 캐시하는 방식을 비교했다. 새 캐시는 자료 스냅샷과 필요한 입력 전체에 결합하고, 반환값 복사·최대 512개·값 크기 제한을 사용했다.

| 구간 / 방식 | 표본 1 중앙값 | 표본 2 중앙값 | 판단 |
| --- | --- | --- | --- |
| DB 기존 | 0.136초 | 0.126초 | 비교 기준 |
| DB 묶음 조회 | 0.110초 | 0.102초 | 해당 구간 약 19% 단축 |
| 세종 규칙 기존 | 0.524초 | 0.389초 | 비교 기준 |
| 근거 확인만 캐시 | 0.514초 | 0.381초 | 약 2% 차이로 효과 미확정 |
| 판정 결과까지 캐시 | 0.672초 | 0.491초 | 약 26–28% 느려져 채택하지 않음 |

DB 실행 횟수는 각각 2,127→11회, 1,699→8회였다. 이미 로컬 SQLite와 파일 캐시를 사용하므로 조회 횟수 감소가 같은 비율의 시간 감소를 뜻하지 않는다. 표본별 DB 구간 절감은 약 0.026초와 0.024초였다.

전체 판정 캐시는 각각 873번 중 4번, 626번 중 0번만 재사용했다. 새 문맥 대부분을 재사용하지 못해 키 생성과 복사의 비용이 추가됐다. 근거 확인 캐시는 각각 13번 중 3번, 6번 중 1번 재사용했지만 시간 차이가 작고 표본·동시 실행 변동이 있어 안정적인 개선으로 확정하지 않는다.

위 표는 첫 번째 예열 통제 측정이다. 시험 드라이버·부품 코드 SHA까지 고정한 확인 측정도 별도로 반복했다. DB 구간은 0.124→0.098초, 0.135→0.117초였고, 두 측정을 합친 관측 단축 범위는 약 13–21%다. 넓은 판정 캐시는 확인 측정에서 0.516→0.659초, 0.382→0.505초로 느려져, 전체 관측 범위는 약 26–32% 지연이었다. 근거 확인 캐시는 0.516→0.513초, 0.382→0.393초로 방향까지 바뀌었으므로 개선을 확정하지 않는다. 확인 측정에서도 모든 반환 객체와 해시가 같았다.

## 검증과 한계

기존·시험 방식의 전체 결과가 모든 회차에서 일치했다. 합성 검사 7개는 묶음 경계·누락 키·NULL·중복 요청·비유일 DB 키·SQL 식별자·크기 제한과 캐시의 문맥/자료 변경·가변 객체 오염·제거·값 크기 제한을 확인했다. 원본 DB는 읽기 전용이며 시험 프로세스의 생산 상태 저장 함수는 차단했다. 낮은 프로세스 우선순위와 여유 메모리 700MiB 하한을 사용했고 큰 사전 모델은 새로 적재하지 않았다.

이 측정은 DB 근거 로딩 및 세종 재적용 구간이다. 나머지 문맥사전 적용, 적격성·요청 계획, 직렬화·압축·디스크 저장·최종 감사는 포함하지 않는다. lookup/캐시 생성 시간도 캐시 구간 측정에서 제외했다. DB 조회 묶기의 전체 보강 시간 단축률이나 완료일 단축은 확인되지 않았다. 현재 실행에는 어느 변경도 적용하지 않고 기존 ETA를 유지한다.

일반화한 시험용 부품은 [묶음 조회·제한 캐시](../../scripts/python/sqlite_readonly_experiments.py), 합성 검사는 [검사 코드](../../tests/test_sqlite_readonly_experiments.py)다. 이 부품 자체는 현재 보강 실행기에 연결되지 않았다. 실제 자료에 결합한 시험 드라이버·상세 측정 영수증·자료 대응은 로컬에 보존한다. 공개 문서에는 원문이나 실제 발화 식별자가 없다.
