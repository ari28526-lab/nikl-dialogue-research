# 소스 단위 재개와 빈도 집계 감사의 검증

2026-10-21, 상태 파일 교체 오류로 긴 감사가 중단된 뒤 재개 구조를 검증했다. 상태 표시 파일이 남아 있다는 사실만으로 작업 생존이나 감사 완료를 판단할 수 없었다. 또한 저장된 변환 결과와 감사의 진행 기록을 구분해야 했다. 변환이 완료되어도 감사에 영속적인 부분 완료 기록이 없으면 행 검증을 다시 수행해야 한다.

이 문서는 구현 원칙과 제한된 검증 결과를 공개한다. 실제 자료에 연결된 실행기·계약·감사 영수증은 로컬에 보존한다. 아래 설명만으로 전체 생산 파이프라인을 재현할 수 있다는 뜻은 아니다. 실행 중인 코드와 이미 통과한 전수 감사는 이 문서 작성 때문에 변경하거나 다시 실행하지 않았다.

## 상태 표시와 완료 기록

상태 JSON은 관찰용이다. 실제 프로세스의 명령줄·부모 관계, 갱신 시각, 오류 로그를 함께 확인한다. 완료 여부는 해당 입력과 출력에 결합된 영수증 및 최종 감사 결과로 판단한다.

상태 파일은 같은 디렉터리의 고유한 임시 파일에 기록하고 flush와 fsync 후 교체한다. Windows 오류 5·32·33은 제한된 횟수만 재시도한다. 한도를 넘으면 기존 파일과 실패한 임시 파일을 보존한다. 일반 갱신은 10초 간격으로 제한하고, 관찰자는 읽기·쓰기·삭제 공유를 허용한 짧은 파일 읽기를 사용한다. Windows의 접근 거부가 모두 일시적 잠금 때문인 것은 아니므로 무한 재시도로 원인 조사를 대신하지 않는다. 실제 실패를 유발한 잠금 주체는 확정하지 않았다.

새 재개 구현에서는 표시 파일 쓰기의 운영체제 오류가 이미 완료된 감사 기록을 지우지 않는다. 입력·출력·영수증 또는 필수 집계의 오류는 표시 오류와 달리 완료로 간주하지 않는다. 파일 교체 및 fsync는 모든 저장장치의 전원 차단 내구성을 보증하는 주장이 아니다.

## 저장과 집계의 재개 경계

각 소스는 독립된 시도 디렉터리에 결과를 쓴다. 필요한 출력과 입력을 확인한 뒤 완료 영수증을 마지막으로 게시한다. 완료 영수증이 없는 임시 출력은 완료 수에 포함하지 않는다.

영수증은 소스 정체성, 부모 영수증, 입력 해시, 실행 계약과 출력 해시·크기를 연결한다. 재개할 때 이 결합을 다시 확인하고, 변경된 입력·출력·계약은 거부한다. 확인된 결과만 재사용한다.

빈도 집계는 SQLite에서 소스 기여분과 반영 완료 표식을 같은 트랜잭션으로 저장한다.

```text
이미 반영된 소스이면 저장된 영수증 해시를 대조한다.
처음 반영하는 소스이면 트랜잭션을 시작한다.
    해당 소스의 빈도 기여분을 합산한다.
    소스 정체성과 영수증 해시를 완료 표식으로 저장한다.
두 변경을 함께 커밋한다.
```

기여분을 넣은 직후 프로세스를 강제 종료하는 시험에서 두 변경 모두 롤백되는 것을 확인했다. 이후 재개와 동일 소스의 반복 반영이 중복 합산을 만들지 않았다. 동시 실행은 별도 실행 잠금으로 차단한다. 중지 표식은 보존하며 소스 경계에서 멈춘다.

## 독립 감사의 재개 경계

감사는 부모 입력을 다시 읽어 기대 빈도를 계산하고 소스별 JSONL·CSV·Parquet의 값을 대조한다. CSV 셀은 JSON 스칼라로 인코딩하므로 문자열과 정수를 복호화한 뒤 비교한다.

감사용 집계 DB는 생산 집계 DB와 분리한다. 소스 검증 후 기대 빈도와 감사 완료 표식을 같은 트랜잭션으로 저장한다. 감사의 결합에는 실행 계약, 저장 완료 기록, 감사 코드의 해시도 포함한다. 재개할 때 완료 소스의 입력·출력·영수증을 재확인하고, 동일성이 확인된 소스의 행 검증만 재사용한다. 해시가 붙었다는 이유만으로 악의적인 기록 변조까지 방어하는 서명 체계로 보지 않는다.

마지막에는 전체 소스 집합과 계수를 확인하고 생산 집계와 감사 집계의 모든 정렬된 행을 대조한다. 그 뒤 코퍼스·단위·모드별 전역 내보내기를 만들고 세 형식의 값을 감사 집계와 다시 비교한다. 내보내기 중 실패한 경우에도 완료된 소스 감사 트랜잭션은 유지된다. 저장 완료와 독립 감사 통과는 별도 상태다.

여기서 독립 감사는 생산 결과를 그대로 정답으로 삼지 않고 부모 입력에서 다시 집계한다는 뜻이다. 빈도 의미 규칙 자체는 공유한다. 따라서 같은 규칙의 의미상 오류가 양쪽에서 반복될 가능성까지 제거하지는 못한다. 합성 사례와 별도의 R 회계 대조가 이를 보완하지만 사람의 의미 판정을 대신하지 않는다.

## 검증 결과와 범위

| 검증 묶음 | 통과 수 | 주요 범위 |
| --- | ---: | --- |
| 별도 소스 감사 재개 | 16 | 실제 프로세스 중단, 남은 행 검증만 재개, 변경·불완전 기록 거부 |
| Windows 상태 교체 | 6 | 실제 삭제 공유 없는 파일 잠금, 제한 재시도, 기존 파일 보존 |
| 빈도 실행기 | 12 | 트랜잭션 강제 종료, 저장·감사·내보내기 재개, 집계 오염·중복·동시 실행 거부 |
| 문자열·좌표 및 빈도 규칙 | 8 | 코드포인트 좌표, 가장자리 공백, 특수 전사, 세 단위 회계 |

실제 자료의 제한된 시험은 서울 4소스와 모두 3소스, 총 15,129형태소였다. 2소스 저장 후 중단하고 재개했을 때 기존 영수증이 바뀌지 않았다. 소스별 결과, 전역 집계, 독립 감사와 14개 전역 내보내기 묶음의 세 형식 대조가 통과했다. R에서도 7소스 CSV와 14개 전역 CSV 묶음의 합계 및 기본형별 동형어 합산·구분 회계가 일치했다. 이 시험은 원자료와 생산 결과를 변경하지 않는 별도 출력에서 수행했다.

분석 문자열 안의 좌표 불일치는 이 표본에서 0이었다. 실제 서울 특수 전사 사례에서는 분석 문자열과 원문 사이의 문자 대응을 확정할 수 없는 2개 토큰의 원문 좌표를 보류했다. 이를 임의의 문자 범위로 채우지 않았다. 분석 문자열 기준 어절 수와 원문 기준 어절 수는 별도로 센다. 형태소·단어 초안·어절의 동형어 합산/구분 빈도는 서로 다른 단위이며, 기계 선택과 미결정 값을 사람 확정 의미로 승격하지 않는다.

위 결과는 재개 기능과 제한된 실제 표본의 통과다. 빈도 전수 실행과 그 최종 감사의 완료를 주장하지 않는다. 이미 통과한 앞 단계의 동일 전수 감사를 기능 시험용으로 반복하지 않았다. 상세 소스 목록·식별자·자료 경로·로그·영수증은 공개 범위에 포함하지 않는다.

## 전수 검증 후속 결과

2026-10-22, 서울 240소스와 모두 17,156소스의 빈도 저장과 독립 감사가 완료됐다. 총 52,492,556형태소이며, 소스별 세 형식 대조, 생산·감사 집계 대조, 14개 전역 묶음의 세 형식 검증이 통과했다. 완료 경계에서 계약·코드·최종 기록, 17,396개 고유 소스 영수증과 전역 출력 42개의 해시를 다시 대조했다. 이 경계 확인을 위해 소스별 전수 행 감사를 반복하지 않았다.

독립 감사용 DB 생성부터 전역 검증 완료까지 약 6시간이 걸렸다. 소스 감사와 전역 내보내기의 개별 소요 시간은 따로 기록하지 않았으므로 분리한 실측치로 제시하지 않는다. 좌표 불일치는 0이며, 서울 특수 전사의 2개 토큰은 원문 좌표 미확정 상태로 보존했다. 이 결과는 자료 연결과 빈도 회계의 검증이며, 기계 의미 선택의 정확도나 남은 의미분석·외부 백업의 완료를 뜻하지 않는다.
