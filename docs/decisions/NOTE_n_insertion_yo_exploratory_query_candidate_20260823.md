## 1. 확정된 처리

보조사 ‘요’ 앞 ㄴ삽입 보고 환경은 본모집단과 분리한 탐색 query 후보로
등록한다. 이 처리 방침은 사용자 D1 결정으로 완료됐으며 다시 결정하지 않는다.

1. 기존 동결 query
   `config/target_queries/n_insertion_production_v1_20260818.json`
   (SHA `744bd8cb…`)를 변경하거나 재동결하지 않는다.
2. 본모집단의 J*/E* 제외 조건을 유지한다.
3. ‘요’ 후보는 별도 모집단·별도 zero-drop 회계로 다룬다.
4. Gate 1에서는 이 문서만 만들며 실행 가능한 query JSON·후보 CSV를 만들지
   않는다.
5. 표면형에는 `요`만 나타나지만 형태소 분석기가 `이/VCP+요/...`처럼 표면에
   없는 `이`를 복원한 사례도 VCP라는 이유로 제외하지 않고 이 탐색 모집단에
   보존한다(2026-08-23 사용자 추가 확정).

## 2. 향후 query 후보의 개념적 조건

다음은 실행 계약이 아니라 후속 설계를 위한 개념적 기록이다.

- 원 표면형·어절 표면형: 해당 위치에 `요`가 나타나고 그 앞에 표면 `이`가
  나타나지 않는 사례 포함
- 형태소 분석: `요/JX`뿐 아니라 표면에 없는 `이/VCP`를 복원한
  `이/VCP+요/...` 계열도 보존
- 오른쪽 POS: `JX` 단독 조건으로 가정하지 말고 실제 태그 분포 확인 필요
- 왼쪽 한글 unit: 자음 종성 존재
- 오른쪽 한글 unit: /j/ 계열 `요`
- 형태소·어절 경계 scope: 실제 말뭉치 분포를 실측한 뒤 별도 결정
- 외래어·L2 전이 사례: 본 탐색 모집단과 구분

`right_pos=VCP`만 보고 제외하면 표면 `/요/` 탐색 사례가 조용히 소실될 수
있다. 실행 query 전에는 원 `form`·어절 표면형과 형태소 분석 연쇄를 대표
사례에서 함께 측정하고, 어떤 열을 표면형 정본으로 쓸지 별도 계약으로 고정한다.

실제 query를 만들 때는 소규모 header·대표 사례 검증, `max_occurrences` 상한,
zero-drop 상태, 기존 출력 비덮어쓰기, 별도 연구자 승인과 SHA 동결을 다시
요구한다.

## 3. 해석 한계

- CLM-0002는 ‘요’ 환경의 직접 보고 근거지만 대화 말뭉치 전체의 실현률을
  확정하지 않는다.
- 표기·형태소 조건은 후보 탐색 근거이며 실제 [n] 실현값이 아니다.
- 기존 QN1/QN2의 941,903행에 ‘요’ 후보가 포함됐다고 해석하지 않는다.
