# 대량 MFA·CSV 전 안전 파이프라인 설계

작성일: 2026-07-24

작업 브랜치: `agent/harden-pre-bulk-pipelines`

기준선 아카이브: `archive/code_pre_bulk_20260724`

## 1. 왜 바꾸었는가

이 연구의 위험은 프로그램이 예외를 내는 것보다, 일부 자료를 빠뜨린 채 성공으로
끝나는 것이다. 이전 실행에서는 MFA가 exit 0과 빈 출력을 함께 반환했고, 부분 CSV는
파일이 존재한다는 이유만으로 완료로 간주될 수 있었다. 이런 오류는 연도·세션·화자에
편중된 결측을 만들며, 음운 변이와 사회변수의 관계를 왜곡할 수 있다.

따라서 성공의 정의를 다음처럼 바꾸었다.

```text
프로세스 종료
  + 입력·출력 개수 일치
  + 스키마·ID·시간구조 검증
  + 구판 보존
  + 실행환경·옵션 기록
  = 연구용 완료
```

## 2. 공통 설계 원칙

### 원본과 파생물 분리

- `D:\00_RAW`: 읽기 전용 원자료
- `D:\10_LAYERS`, `D:\20_AUDIO`: 검증된 파생 레이어
- `C:\mfa_tmp`, `D:\mfa_tmp`: 실패 시 보존하는 재개 상태
- 프로젝트 `work`: 파일럿·합성 검증
- 프로젝트 `logs`, `outputs/reports`: 실행 증거와 사람이 읽는 결과

### 원자적 승격

CSV와 JSON은 완성 경로에 직접 쓰지 않는다. 같은 디렉터리의 고유한
`.partial` 파일에 기록하고 `flush`와 `fsync`를 수행한 뒤, 스키마·행수·ID를
검증하고 `os.replace`로 승격한다. 중단되면 불완전 파일은 증거로 남고 기존
정식 파일은 그대로다.

### 구판 보존

정식 파일을 교체할 때 기존 파일은 `_archive/<run_id>/...`에 `copy2`로 먼저
보존한다. 같은 실행 ID의 아카이브가 이미 있으면 덮지 않고 실패한다. Git에
들어가는 코드 기준선은 SHA256 manifest와 함께 별도 보존했다.

### 실패를 성공으로 번역하지 않기

- PowerShell 치명 분기는 `exit 1`을 사용한다.
- 대상 연도·세션이 0개이면 실패한다.
- 구현되지 않은 `--coverage`는 빈 값을 만드는 대신 실패한다.
- 마커는 구조화된 JSON이며 실제 산출 검증 뒤에만 원자적으로 만든다.
- 오래된 문자열 마커, G2P 정보가 없는 마커, 출력만 남은 모호한 상태는 자동
  진행하지 않는다.

## 3. MFA 경로 개선

### 실행 전

`preflight_eojeol_realign.ps1`은 다음을 한 번에 확인한다.

1. D: 볼륨 레이블 `DATA_SSD`와 C:/D: 여유 공간
2. 고정 Python 실행기와 모든 helper script
3. `mfa`, acoustic model, dictionary, `korean_mfa` G2P model
4. 프로젝트 밖 MFA 설치본의 필수 패치 7종과 대상 파일 SHA256
5. 연도별 세션 폴더 구조, 기존 temp·출력·마커의 일관성

MFA 3.4.0의 수동 패치는 버전 문자열만으로 재현할 수 없다.
`verify_mfa_install.py`가 AST와 소스 패턴으로 다음을 검사한다.

- `analyze_alignments()` 호출 제거
- export format 전달 두 곳
- export worker의 `output_path` 선행 초기화
- 예외 시에도 완료 플래그를 세우는 `finally`
- SQLite 대상 50,000개 이하 청크 처리

### 실행 중·후

- 잘못된 WAV는 상대 세션 경로를 보존한 격리 폴더로 옮기며, 작업 전 계획과
  완료 상태를 JSON transaction으로 남긴다.
- 코퍼스 lab은 0바이트가 아닌 기존 파일만 재사용하고 새 파일은 원자적으로 쓴다.
- MFA stderr는 영구 로그로 남긴다.
- align 결과는 lab 대비 99% 이상이며 TextGrid가 0개가 아닐 때만 완료로 본다.
- 병합기는 `words`, `phones`, `morphemes`, `sense` 네 tier의 이름·순서·시간
  경계·전체 duration을 검증한다.
- 성공 마커를 쓴 다음에만 해당 연도의 temp를 정리한다. 삭제 대상은 허용된
  부모 경로 아래인지 확인한다.

## 4. 메타데이터·검색 CSV 경로 개선

### 발견된 원자료 불일치

2023년 JSON 네 파일의 최상위 `id`가 직전 세션 ID로 기록되어 있었다.

| 정본 파일 stem | 원본 최상위 `id` |
|---|---|
| `SDRW2300000445` | `SDRW2300000444` |
| `SDRW2300000457` | `SDRW2300000456` |
| `SDRW2300000473` | `SDRW2300000472` |
| `SDRW2300001337` | `SDRW2300001336` |

구 빌더는 최상위 `id`를 `file_id`로 써 4개 중복 행을 만들었다. 행 수만
확인하면 17,156으로 정상처럼 보이지만 실제 세션 4개의 문서 메타가 없었다.

새 빌더는 배포 파일명 stem을 세션 좌표 정본으로 사용한다. 내부 `document.id`와
모든 `utterance.id`가 그 stem으로 시작하는지도 확인한다. 잘못된 최상위 값은
수정하거나 버리지 않고 마지막 컬럼 `source_top_id`에 보존한다. 즉, 분석 조인은
복구하되 원자료의 이상은 추적 가능하다.

### 검색 마스터

- 형태분석 CSV 세션 ID와 `file_meta.csv`의 `file_id` 집합이 정확히 같은지
  preflight에서 전수 대조한다.
- 메타 로더는 빈 ID와 중복 ID를 즉시 실패 처리한다.
- 세션 CSV는 `utt_id` 순서·개수·중복, 헤더, 어절 정합을 검증한다.
- 유효한 기존 CSV만 재사용하고, 부분·구식 파일은 자동 아카이브 후 재생성한다.
- 실행 manifest에는 Git commit, Python, OS, 옵션, 경로, 합계, 판정을 기록한다.
- 연구 결측(`미상`)과 아직 계산하지 않은 값(`미계산`)을 구분한다.

## 5. 검증 전략

검증은 네 층으로 나눈다.

| 층 | 질문 | 방법 |
|---|---|---|
| 정적 | 실행기가 위험한 제어 흐름을 갖는가 | PowerShell AST, BOM, 소스 패치 검사 |
| 합성 | 고장 난 입력에서 기존 결과가 보존되는가 | 부분 CSV, 잘못된 tier, 0바이트 WAV, ID 충돌 실패 주입 |
| 전수 입력 | 대량 실행 전에 좌표와 환경이 완전한가 | 17,156 JSON/형태분석/메타 ID 집합, MFA 설치·모델·디스크 검사 |
| 소표본 내용 | 결과 열이 실제 연구 변수로 채워지는가 | 복구 세션 216발화 CSV, G2P 파일럿과 이후 청취 표본 |

구조 검증은 음운론적 타당성을 대신하지 않는다. 예를 들어 G2P의 `spn=0`은
발음 후보가 생성됐다는 뜻이지 발음이 정확하다는 뜻이 아니다. 본 MFA 전에 연음,
경음화, 비음화 등 현상별 자동 표본과 청취 표본을 별도로 승인해야 한다.

### MFA

실패 시 temp·원출력·stderr·JSON 마커를 보존한다. 재실행 전에 preflight로
마커의 year·stage·G2P·출력 경로를 확인하고, 모호한 상태를 수동으로 해석한 뒤
진행한다. temp 삭제는 검증 완료 후 해당 연도 경로에만 허용된다.

## 7. 대량 실행 전 남은 승인점

1. MFA 소표본에서 의도적 실패와 재개를 한 번 더 실증한다.
2. G2P phones의 현상별 자동 QC와 사람 청취 표본을 승인한다.
3. CSV는 복구된 세션 외에 연도별 몇 세션을 층화 파일럿으로 확인한다.
4. 그 결과가 통과한 커밋 ID를 본 실행 manifest의 기준 커밋으로 고정한다.

이 네 조건 전에는 대량 MFA나 510만 발화 검색 마스터 생성을 시작하지 않는다.
