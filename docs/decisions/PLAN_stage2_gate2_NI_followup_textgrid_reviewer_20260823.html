새 화면에서 하는 일

  1. 1TextGrid 후속 검토가 불필요 / 필요 / 불확실인지 고릅니다.
  2. 2필요한 이유를 경계·label·전사·표적 span·기타에서 여러 개 고릅니다.
  3. 3운율·의미번호·화자 정보처럼 더 확인할 정보와 이유를 여러 줄로 적습니다.
  4. 4후속 필요성 판단의 확신도를 1–5로 기록합니다.
  5. 5필요/불확실이면 같은 화면의 TextGrid 패널이 자동으로 열립니다.

패널에는 파형·재생 위치, 표적 시간 강조, 6개 tier의 label·경계, source SHA와 자산 상태를 보여줍니다. 클릭은 재생 위치만 옮기며 경계는 바꾸지 않습니다.

기존 “들린 형식의 확신도(높음/중간/낮음)”와 새 “후속 검토 필요성 확신도(1–5)”는 뜻이 다르므로 별도 필드로 보존합니다.

저장과 다음 단계 queue

  • 기존 JSONL 15행은 그대로 보존합니다.
  • 새 저장분만 pv_reviewer_event.v3 revision이 됩니다.
  • 내보내고 다시 가져오면 같은 exact-ID에 복원됩니다.
  • 최신값이 required 또는 unsure인 사례만 별도 queue 후보 JSONL로 내보냅니다.
  • 이 queue는 Gate 3의 입력 후보일 뿐, 정식 작업본·sidecar·ledger가 아닙니다.
textgrid_review_need: not_needed | required | unsure
textgrid_asset_status: available | unavailable | blocked
manual_task_status: not_created | queued | exported | returned | audited

세 축은 독립입니다. 예를 들어 “검토는 필요하지만 파일은 없음”은 required + unavailable로 그대로 기록할 수 있습니다.

지금 보이는 “핵심/탐색” 우선순위 문제

현재 v2.1의 core/exploratory는 2026-08-19 기술 파일럿용 태그입니다. 일반적인 형태론 환경을 먼저 본다는 연구 우선순위가 아닙니다.

  • Gate 2에서는 큰 배지와 정렬 필터로 쓰지 않습니다.
  • 감사 정보에 “이전 PV-A 표본 태그 — 연구 우선순위 아님”으로만 남깁니다.
  • 같은 형태소 조합·단어별 묶기와 불확실 사례 재검토 정렬은 실제 occurrence에 환경 유형을 배정한 뒤 구현합니다.

지금 NI 두 건에 임의로 새 우선순위를 붙이면 Gate 1의 occurrence_assignment_status=not_started를 우회하게 되므로 하지 않습니다.

구현 후 무엇을 검사하나

  • 입력 14 = 출력 14, NI 2와 비NI 회귀 표본 12의 역할 분리
  • TextGrid 14/14 존재·SHA·6-tier·시간 범위
  • 자동 펼침, 1–5와 복수 요청 저장·복원, queue 필터
  • 기존 15행 보존, 최신 revision 선택, 미저장 경고

  • 원본 수정 0, 자동 실현 판정 0, ledger 쓰기 0
  • Python compile·단위 시험·브라우저 runtime 시험·PowerShell 5.1 preflight
