## 핵심 발견

정렬 실패 19건이 넓은 beam에서 모두 TextGrid를 얻었지만, 18건은 연구 본체에
그대로 넣을 수 없었다. 주된 이유는 음향모델 성능 자체보다 클립의 실제 발화와
LAB 사이의 범위 불일치였다.

- LAB 뒤에 실제로 없는 문장이나 어절이 붙음
- 같은 구절이 두 번 중복됨
- 실제 어휘와 LAB 어휘가 다름
- 끝 단어가 일부만 녹음되거나 클립이 먼저 끝남
- 이 과잉 텍스트가 짧은 실제 음성에 강제로 압축 배정되어 word·phone 경계가 밀림

따라서 `TextGrid 생성 성공`은 기술적 회수 성공이지 언어학적·음향적 사용 승인과
같지 않다. 이 구분은 향후 recovery shard에도 동일하게 적용한다.

자동 `source_overlap=true`였던 네 건 중 실제 두 화자 겹침은 5번 한 건뿐이었다.
3·4·8번은 각각 겹침 없음 또는 일반 배경소음으로 연구자 청취 판정을 우선했다.
TV/배경음악이 있는 16·17번은 단일 화자 자동 음향분석과 구분하되 수동 분석은
가능한 것으로 보존했다.

## 보존 및 수정 정책

원 WAV·LAB·D9 TextGrid는 덮어쓰거나 삭제하지 않는다. 16건은 실제로 들린 문장을
별도 수정 전사로 만들고 수동 `words`·필요시 `phones` 경계를 overlay에 기록한다.
간단한 끝부분 삭제·중복 제거 사례와 전체 수동 재정렬 사례를 난이도별로 나눈다.
수정 전사와 경계는 원본이 아니라 exact-ID 기반 파생본으로 DB에 연결한다.

2건의 기술 제외도 파일을 삭제하지 않고 제외 이유와 함께 증거로 보존한다. 1건의
승인 정렬 역시 바로 r3 본체를 덮어쓰지 않고 6-tier enrichment와 DB overlay를
별도 채택 계약 아래 수행한다.
