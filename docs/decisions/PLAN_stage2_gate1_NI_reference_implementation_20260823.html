1. 무엇을 하는 단계인가

NI의 동결 query와 문헌 근거 사이에 연구 계약을 만들고, 일반·주변·탐색· 불명 환경을 환경 유형 단위로 정리한다. 개별 발화의 실현을 판정하거나 94만 행에 환경 클래스를 자동 부여하는 단계가 아니다.

하지 않음: query 재동결, ‘요’ query JSON, 후보 재생성, G5/G6, MFA·KOINA·wav2vec2, TextGrid 수정, 자동 실현 판정, 정식 ledger.

4. ‘요’는 무엇이 남았나

결정은 끝났다. 본모집단과 분리하고, 기존 query를 바꾸지 않으며, 탐색 후보로 기록한다.

Gate 1에서 남은 일은 이 결정을 후보 문서로 옮기는 것뿐이다. 실제 query JSON 생성·동결은 하지 않는다. 이후 사용자 결정 목록에 ‘요’를 다시 넣지 않는다.

5. 사람 확인 문헌

  • CLM-0015: 한자어 공명음/장애음 비대칭 — 계약 동결 전 우선 확인.
  • CLM-0008: ㄴ탈락과의 이론 관계 — inclusion 조건이 아니면 유보 가능.
  • CLM-0026: 연령·지역 변이 — 세부 수치를 쓰지 않으면 qualitative confound로 유보 가능.
  • CLM-0145·0151은 HIA 착수 때 확인.

6. 구현 GO 뒤 만들 파일

  1. 6개년 candidate source registry
  2. NI inclusion/exclusion/confound candidate 계약
  3. NI 환경 유형 candidate JSONL
  4. CLM 연결을 갖춘 새 NI definition
  5. ‘요’ 탐색 query 후보 문서
  6. 독립 검사기와 테스트
  7. 감사 JSON·SHA manifest·검증 로그

계약은 먼저 candidate로 만들고, 연구자 확인 뒤 새 frozen 버전을 만든다. 기존 파일은 덮어쓰지 않는다.

7. 합격 조건

  • query·join SHA와 6개년 manifest·감사 결속
  • 34/73열 헤더 동일성과 match_evidence_json 필수 key 확인
  • query 조건과 연구 계약의 모순 0
  • 모든 환경 유형에 evidence ref 또는 pending
  • 잘못된 SRC/CLM·SHA·필드 누락을 테스트가 차단
  • 941,903행 zero-drop 기준선 유지
  • 기존 출력 비덮어쓰기와 .partial 원자 승격

8. 사용자가 다음에 확인할 것

  1. 환경 유형 seed를 candidate 상태로 만드는 데 동의하는가?
  2. source registry·계약·환경 유형·새 definition·‘요’ 문서·검사기·감사만 구현하는 데 동의하는가?

이 두 항목에 GO가 있기 전에는 구현하지 않는다.
