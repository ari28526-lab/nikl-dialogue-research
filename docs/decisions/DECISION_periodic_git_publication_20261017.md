# 검토한 작업의 정기 GitHub 보존

2026-10-17 사용자가 게시할 변경이 있으면 주기적으로 commit과 push를 진행하도록 승인했다. 매번 같은 게시 승인을 다시 받지 않고, 아래 범위와 실제 diff를 확인해 진행한다. 이 결정은 연구 원자료나 로컬 결과의 포괄적인 공개 승인이 아니다.

단계 완료 시와 기존 정기 점검에서 변경을 검토한다. 공개에 적합한 변경이 없으면 빈 커밋을 만들지 않는다. 검증된 일반화 코드, 그 코드와 의존성이 함께 제공되는 합성 시험, 공개 가능한 방법·결정 문서를 구체적인 파일 목록으로 선정한다. 과거 미커밋 변경 전체를 이번 승인 대상으로 간주하지 않는다.

게시 전에는 선정 파일의 전체 내용과 최종 diff, 의존성, 관련 검사 결과를 확인한다. 원문·실제 발화/화자 식별자·개인 절대경로·비밀값·기기 식별자·상세 원본 목록·대용량 결과/로그·로컬 단계 등록부는 제외한다. 공개 문서에서 로컬 전용 근거를 공개 저장소에 존재하는 링크처럼 표시하지 않는다. 코드가 아직 로컬 계약에 결합되어 있으면 공개 보류 사유를 기록한다.

활성 생산 코드·계약·장부를 게시 준비 때문에 바꾸지 않는다. 실행이 끝난 뒤 별도 수정판에서 일반화하고 필요한 검증을 거친다. 공개된 방법 문서만으로 로컬 생산 코드 전체를 재현할 수 있다고 주장하지 않는다.

현재 branch·upstream과 원격 상태를 확인하고 명시한 파일만 stage한다. `git add .`, 다른 작업의 stage 포함, force push, 인증정보 노출은 하지 않는다. 기존 미검토 변경은 그대로 둔다. 인증·네트워크·충돌 문제로 게시하지 못하면 로컬 결과와 실패 상태를 보존하고 보고한다.

완료 시 커밋 ID, 게시한 범위, 검증 결과를 로컬 진행 기록과 연속성 체크포인트에 남긴다. 단계 완료 보고에는 그 단계의 결과·보류와 다음 단계 및 전체 잔여 예상 시간도 함께 포함한다. 시간 추정에는 기준 시각·실측 범위·불확실성을 표시한다.

GitHub 게시 승인은 별도 클라우드 백업의 업로드 범위, 유료 사용권, 구매 승인 범위를 변경하지 않는다. 기존 체크포인트 작성기는 계속 기록만 담당하며 commit·push는 별도 검토 단계로 수행한다.
