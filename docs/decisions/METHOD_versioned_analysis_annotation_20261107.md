# 분석판 선택과 Group ID 주석 기록

새 형태소 분석판은 전체 저장과 독립 감사가 같은 계약으로 통과한 뒤 검색에 등록한다. 등록에는 분석판 이름, 원본 결과·감사·소스 영수증의 해시, 사전판과 DB 해시를 포함한다. 등록 파일과 연구 자료는 로컬에 보존한다.

## 검색

scripts/python/analysis_release.py의 register 명령으로 별도 카탈로그 파일을 만든다. context는 분석판·코퍼스·소스·발화 ID를 모두 지정해 문맥과 새 분석을 조회한다. search는 기본형과 선택적 품사로 조회하며, source를 지정하면 해당 소스로 범위를 좁힌다. source를 생략하면 코퍼스 소스를 순서대로 읽어 limit에 도달하면 멈춘다. 이 결과의 건수는 전수 빈도가 아니다.

groups는 사전의 Group ID를 기준으로 동형이의어 후보를 묶는다. 뜻풀이 항목은 판단 근거로 제공하며 같은 Group 내부의 세부 뜻 선택은 요구하지 않는다. 형태소 분석 응답의 뜻풀이 target ID가 있으면 선택한 사전판에서 Group ID로 조회할 수 있다. 그 연결의 존재와 연구자 의미 확정은 구분한다.

기존 query_delivery_links.py의 문맥·음성 조회에 analysis-catalog, analysis-version, analysis-source를 함께 지정하면 같은 발화 ID의 새 분석을 selected_analysis 필드로 연결한다. 기존 음성·TextGrid 참조와 문자·시간 좌표의 종류를 보존한다. 원자료의 정렬 부재는 새 분석으로 채우지 않는다.

## 선택 사례 검토

apps/variation_review/build_release_data.py는 기존 선택 검토 표본을 새 판에 다시 연결한다. 원문과 표적 문자 범위, 기본형·품사가 대응하는 사례에 새 사전 후보를 붙인다. 불일치 사례는 형태 검토 보류로 남긴다. 새 분석판의 출현 ID와 content hash를 생성하며 이전 확정 판단은 부모 출현 참조로 연결한다.

server.py의 dataset 옵션으로 검토할 스냅샷을 지정한다. 자료판별로 별도 reviews.sqlite를 사용한다. 이전 스냅샷과 판단 DB도 다시 열 수 있다.

검토 화면의 ‘주석 입력 내려받기’는 지침판·사전판·문맥·경쟁 분석·Group 후보 및 출력 계약을 내보낸다. ‘모델 제안 기록’은 원출력과 파싱 결과를 저장한다. 형식 오류와 후보 밖 ID도 원출력과 함께 보존한다. 모델 제안을 저장해도 연구자 확정 상태는 바뀌지 않는다. 판단은 기존 후보 선택·품사 확인·저장 흐름으로 기록한다.

제안 기록은 온라인 검토 서버의 기능이며 현재 휴대용 HTML의 답변 교환 형식에는 포함하지 않는다. 공개 데모의 구현 원리를 참고해 기존 앱에 독립적으로 구현했으며 외부 소스를 복사하지 않았다.

## 검증 범위

합성 시험은 감사 미통과 등록 차단, 사전·소스 변조 탐지, Group별 후보 묶음, 새 출현 ID와 판단 승계 방지, 원출력 보존, 입력판 충돌·중복 저장, HTTP 저장 경로를 다룬다. 실제 새 분석판의 검색 등록과 선택 사례 재연결은 별도 로컬 검증 보고서로 확인한다. 기술 검증 통과를 언어학적 정답 정확도로 표현하지 않는다.
