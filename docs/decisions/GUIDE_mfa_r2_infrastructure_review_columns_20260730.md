## 1. 이 검토표가 필요한 이유

이 프로젝트의 최종 연구 흐름은 다음과 같다.

1. CSV/Parquet에서 특정 형태소 또는 표기상 음운 환경을 검색한다.
2. 같은 `utt_id`를 이용해 WAV와 TextGrid를 모은다.
3. 선택 후보에 KOINA 운율 정보와 필요 시 이어붙이기 결과를 결합한다.
4. 연구자가 음성과 TextGrid를 직접 보고 실제 실현 여부를 별도로 판정한다.

따라서 대량 MFA를 시작하기 전에는 정렬 성공률만 볼 것이 아니라, 검색 결과가
올바른 음성·TextGrid로 이어지고 그 자료가 실제 연구자 검토에 편리한지
확인해야 한다. `REVIEW.xlsx`의 열은 이 인프라 수용 여부를 60발화에 대해
일관된 방식으로 기록하기 위해 만든 것이다.

기계 QC는 이미 6개년 모두 통과했다. 이 표의 역할은 기계 검사를 반복하는
것이 아니라, 기계가 놓치기 쉬운 **연결의 의미적 정확성**과 **연구자
사용성**을 확인하는 것이다.

15개 열의 이름을 사용자가 하나씩 직접 지정한 것은 아니다. 다음 직접 요청을
검토 가능한 필드로 운영화한 결과다.

| 사용자 요청·문제 제기 | 필요한 검토 기능 | 대응 열 |

| 파일을 일일이 찾기 번거로우므로 연도별 WAV·TextGrid·LAB·CSV를 함께 보고 싶음 | 같은 발화의 네 파일을 즉시 열고 연결 확인 | `linkage_status`, 네 파일 링크 |
| 파일럿을 가능한 한 한 폴더에 모으고 싶음 | 이동 가능한 상대경로와 공통 접두사 | `wav_file`, `textgrid_file`, `lab_file`, `csv_file` |

| 대화 자료에서는 화자와 대화 참여자 정보를 나중에 다시 찾을 수 있어야 함 | 화자·세션·발화 join key 보존 | `speaker_id`, `session_id`, `utt_id` |

열은 두 종류로 나뉜다.

- **사용자 요청에 직접 대응하는 열**:
  연결, tier, 경계, CSV 검색성, 화자·세션, 파일 링크
- **안전한 운영을 위해 파생한 열**:
  검토 순서, 종합 결정, 자유 메모, 불변 식별자

## 3. REVIEW.csv와 REVIEW.xlsx의 관계

자료 흐름은 다음과 같다.

```text
selection_manifest.csv
  → REVIEW.csv                     기계 생성 기준 정본
  → REVIEW.xlsx                    연구자 입력 편의 사본
  → validate_mfa_r2_review_workbook.py
  → normalized decision CSV        검증된 연구자 결정
  → researcher review JSON         승인/수정필요/미완/불일치 판정
```

- `REVIEW.csv`는 생성 당시의 열·행·파일 연결을 보존하는 기준이다.
- `REVIEW.xlsx`는 연구자가 노란 열에 쉽게 입력하도록 만든 편의 사본이다.
- 작성 뒤에는 XLSX 전체를 그대로 신뢰하지 않는다. validator가 불변 열을
  원본 CSV와 전수 비교하고, 허용된 여섯 열만 회수한다.
- 이 방식은 실수로 `utt_id`, 화자, 세션, 파일 링크가 바뀐 검토표가 승인
  근거로 사용되는 것을 막는다.

## 6. 불변 식별·표본 열

### 6.1 `review_order`

**무엇을 나타내는가**

- 패키저가 `selection_manifest.csv`의 행을 읽은 안정적인 순서다.
- 현재 값은 1–60이며 연도별 10행씩 묶여 있다.

**왜 필요한가**

- Excel에서 연도·상태·화자별로 정렬한 뒤에도 원래 검토 순서로 돌아갈 수
  있다.
- 중간에 멈췄을 때 “몇 번까지 확인했는가”를 간단히 기록할 수 있다.

**어떻게 활용하는가**

- 연도별 첫 사례인 1, 11, 21, 31, 41, 51번을 먼저 보아 판정 기준을
  맞출 수 있다.
- 언어학적 의미나 원자료 ID는 없으므로 join key로 사용하지 않는다.

### 6.2 `year`

**무엇을 나타내는가**

- 해당 발화가 속한 NIKL 대화 말뭉치 연도다.
- 녹음일 또는 검토일을 뜻하지 않는다.

**왜 필요한가**

- 2020–2025가 같은 모델·사전·phone 기준으로 처리됐는지 연도별로 확인한다.
- 연도별 구조 차이나 특정 연도에 몰린 오류를 발견할 수 있다.

**어떻게 활용하는가**

- 연도당 10발화·5화자·5세션 균형을 확인한다.
- 문제 메모를 연도별로 묶어 후속 수정 범위를 정한다.

### 6.3 `utt_id`

**무엇을 나타내는가**

- 발화를 모든 레이어에서 연결하는 정본 식별자다.
- 예: `SDRW2000001214.1.1.95`

**왜 필요한가**

- CSV 검색 결과에서 WAV·TextGrid·LAB·원 JSON을 다시 찾는 핵심 join key다.
- 파일 이름이 비슷하거나 세션 경로가 달라도 동일 발화임을 증명한다.

**어떻게 활용하는가**

- 네 파일 이름의 `연도__utt_id` 접두사가 이 값과 같은지 확인한다.
- 향후 KOINA·stitch·wav2vec2·연구자 실현 판정도 이 키로 연결한다.
- 사람이 읽기 어렵더라도 수정하거나 축약하지 않는다.

### 6.4 `speaker_id`

**무엇을 나타내는가**

- 메타데이터에서 확인한 실제 화자 식별자다.

**왜 필요한가**

- 과거 평면 폴더 때문에 연도 전체가 한 화자로 오인된 시행착오가 있었다.
- 연구 표본이 특정 화자에 몰리지 않았는지 확인해야 한다.

**어떻게 활용하는가**

- 연도별 실제 화자 5명, 화자당 2발화 조건을 확인한다.
- 후속 연구에서 화자별 반복측정·무작위효과·오류 집중도를 분석할 수 있다.
- `session_id`와 같다고 가정하지 않는다.

### 6.5 `session_id`

**무엇을 나타내는가**

- 발화가 속한 원 녹음 또는 대화 세션 식별자다.

**왜 필요한가**

- 실제 파일은 연도/세션 경로에 있고 MFA도 세션 디렉터리를 화자 단위로
  해석하는 경우가 있다.
- 같은 화자의 여러 세션과 같은 세션의 여러 발화를 구분해야 한다.

**어떻게 활용하는가**

- 원자료 경로 복원, 같은 대화 주변 발화 이어붙이기, 세션 단위 오류 추적에
  사용한다.
- 현재 파일럿은 연도별 서로 다른 세션 5개를 포함한다.
- `speaker_id`와 독립된 열로 보존한다.

## 7. 연구자 입력 열

### 7.1 `linkage_status`

**질문**

> 같은 행의 WAV·TextGrid·LAB·CSV가 실제로 같은 발화를 나타내는가?

**사용자 요청과의 관계**

- 파일을 일일이 찾아다니지 않고 한 폴더에서 같은 발화 자료를 확인하고
  싶다는 직접 요청을 운영화한 열이다.

**`통과` 기준**

- 네 파일이 모두 열린다.
- 파일 이름의 연도와 `utt_id`가 행 값과 같다.
- WAV에서 들리는 발화와 LAB/CSV/TextGrid utterance의 내용이 대략적으로
  같은 발화다.
- `speaker_id`와 `session_id`가 CSV·표본 정보와 충돌하지 않는다.

**`문제있음` 기준**

- 음성과 전사가 다른 발화다.
- 같은 ID처럼 보이지만 연도·화자·세션이 다르다.
- 링크나 파일이 없거나 다른 파일을 연다.
- LAB과 CSV가 서로 다른 입력 전사를 가리킨다.

**후속 활용**

- 연결 문제는 MFA 정확도 문제가 아니라 먼저 join/패키징/원자료 탐색
  코드로 routing한다.

### 7.2 `tier_structure_status`

**질문**

> TextGrid의 네 tier가 모두 존재하고 출처와 역할에 맞게 연구 검토에
> 사용할 수 있는가?

현재 4-tier 출처는 다음과 같다.

| tier | 출처 | 이 단계의 용도 |
|---|---|---|
| `words` | MFA word intervals | 어절의 대략적 위치·탐색 |
| `phones` | MFA phone intervals | 정렬·탐색 보조 |
| `morphemes` | 기존 `06_textgrid_merged`의 words 경계 | 형태소 위치 보조 |
| `utterance` | 동결 검색 마스터의 `form` | 발화 전사·ID 연결 |

**사용자 요청과의 관계**

- TextGrid에 tier가 너무 많았고 출처가 불명확하다는 문제 제기, 그리고
  연구 목적에 맞으면 더 줄여도 좋다는 요청을 반영해 운영본을 네 tier로
  줄였다.

**`통과` 기준**

- 네 tier가 한 번씩 존재한다.
- tier가 비정상적으로 비어 있거나 중복되지 않는다.
- 라벨과 시간구간이 전체적으로 읽을 수 있고 발화와 크게 어긋나지 않는다.

**오류로 보지 않는 것**

- `phones`가 실제 들리는 발음과 세부적으로 다른 것
- 격음·경음·유성성 등 미세한 phone 해석 차이
- `morphemes` tier가 gold 형태소 분석 자체가 아닌 legacy 위치 보조층인 것

**후속 활용**

- 누락·중복은 export/후처리 문제로, 전체 시간 이동은 정렬 문제로 분리한다.

### 7.3 `boundary_status`

**질문**

> 모든 tier가 발화 전체 시간영역을 덮고, 연구자가 처음과 끝을 확인하거나
> 이어붙일 때 경계가 충분히 명확한가?

**사용자 요청과의 관계**

- 이전 검토본에서 일부 tier의 처음·끝 경계가 빠져 보였고, 검색·이어붙이기를
  위해 모든 tier의 양끝 경계가 필요하다는 직접 피드백을 반영했다.

이 열에서는 두 종류의 경계를 구분한다.

1. **구조적 경계**
   - 모든 interval tier가 `0–WAV xmax`를 gap·overlap 없이 연속적으로 덮는다.
   - 이 항목은 기계 QC도 검사했지만 사람이 Praat에서 의미상 잘린 구간을
     추가로 확인한다.
2. **가시적·사용성 경계**
   - 발화가 파일 끝에 붙어 있더라도 연구자가 tier의 처음·끝을 식별하기
     쉬운가?
   - 운영 TextGrid는 무padding 원칙이므로 0.05초 빈 여백이 항상 존재하는
     것은 아니다. 가시적 빈 interval이 연구 작업에 필요하지만 부족하다면
     구조 오류와 구별해 notes에 남긴다.

**`통과` 기준**

- tier가 중간에서 시작하거나 끝나지 않는다.
- 마지막 phone/word가 WAV 밖으로 나가거나 조기에 잘리지 않는다.
- 빈 선행·후행 무음은 빈 interval로 해석 가능하다.
- 현재 검토·검색·이어붙이기 방식에서 경계를 식별하는 데 문제가 없다.

**후속 활용**

- 구조적 실패는 4-tier exporter gate를 수정한다.
- 가시성 문제만 있으면 운영본을 바꾸지 않고 검토 사본 padding 또는
  stitch 표시 방식을 보완할 수 있다.

### 7.4 `csv_searchability_status`

**질문**

> 이 발화의 CSV 구조와 열이 향후 형태소·표기 환경 후보 검색 및 원자료
> 회수에 충분한가?

**사용자 요청과의 관계**

- 특정 형태소 또는 표기상 환경을 먼저 CSV에서 찾고 해당 음성·TextGrid를
  모으는 것이 전체 연구 흐름이라는 직접 설명을 반영한다.
- 형태소별·어절별 철자 로마자, 규칙 발음, 사전 예외 발음, 화자/대화
  참여자 정보가 필요하다는 요청도 이 열의 판단 근거다.

**중요한 한계**

- 각 `csv_file`은 전체 검색 마스터가 아니라 해당 발화의
  `pilot__*` 표본 정보와 `search__*` 동결 검색 행을 합친 **1행 점검
  snapshot**이다.
- 현재 동결 pre-MFA CSV는 MFA 입력에는 충분하지만 최종 연구 검색
  CSV/Parquet가 완성됐다는 뜻은 아니다.
- 이 검토는 1행에서 열의 존재·의미·값·join 가능성을 살피는 것이다.
  510만행 전수 검색 성능을 검증하는 단계는 아니다.

**확인할 내용**

- `utt_id`, 연도, 화자, 세션으로 원자료를 다시 찾을 수 있는가?
- `form`, `original_form`, `pron_reference_form`의 역할이 구별되는가?
- 형태소 표기·품사·어절/형태소 index가 검색에 충분한가?
- 형태소별·어절별 철자 기반 로마자가 존재하고 비어 있지 않은가?
- 규칙 발음과 우리말샘/사전 발음이 출처가 다른 보조열로 구별되는가?
- 숫자 `1`, 기호, 외국어 등이 무근거 빈칸으로 사라지지 않는가?
- 같은 `utt_id`로 WAV/TextGrid/KOINA/후속 판정을 붙일 수 있는가?

**`문제있음`으로 기록해야 하는 경우**

- 연구에 필요한 형태소 또는 철자 로마자 열이 없다.
- 발음 열의 출처가 구별되지 않는다.
- 핵심 ID·화자·세션 값이 비어 있거나 재탐색할 수 없다.
- 기호·숫자 처리 때문에 원표기와 MFA 입력의 관계를 알 수 없다.

필요한 검색 열이 현재 snapshot에 없으면 “나중에 만들 예정”이라는 이유만으로
통과시키지 않는다. 어떤 열이 부족한지 notes에 기록해야 최종 검색
CSV/Parquet 설계의 수정 요구로 남는다.

### 7.5 `overall_infrastructure_decision`

**질문**

> 이 발화가 향후 후보 검색→파일 수집→운율 결합→연구자 판정을 위한
> 인프라 표본으로 수용 가능한가?

**사용자 요청과의 관계**

- 파일럿을 한 뒤 대량 작업으로 넘어가자는 결정과, 모두 끝낸 뒤 처음부터
  다시 하지 않도록 중간 문제를 추적해야 한다는 요청을 gate로 운영화했다.

**판정값**

- `미검토`: 아직 판단하지 않음
- `인프라 통과`: 네 구성 항목이 모두 `통과` 또는 정당한 `해당없음`
- `수정 후 재검토`: 하나 이상의 실제 수정이나 설계 결정이 필요함

**일관성 규칙**

- 구성 항목에 `미검토` 또는 `문제있음`이 있는데 종합을
  `인프라 통과`로 두면 validator가 불일치로 판정한다.
- `수정 후 재검토`이면 `notes`에 이유를 적어야 한다.
- 이 값은 “해당 발화에서 ㄴ 삽입이 실현됐다” 같은 언어학 판정이 아니다.

### 7.6 `notes`

**무엇을 나타내는가**

- dropdown으로 표현하기 어려운 문제 위치·정도·수정 요구를 기록한다.

**왜 필요한가**

- `문제있음`만으로는 코드, 자료, 정렬, 경계, CSV 중 무엇을 고쳐야 하는지
  알 수 없다.
- 시행착오를 연구 방법론과 후속 회귀시험으로 전환하려면 구체적 근거가
  필요하다.

**권장 형식**

```text
[연결] WAV와 utterance 전사가 다른 발화로 보임
[tier] morphemes tier가 비어 있음
[경계-구조] phones가 WAV 끝 0.18초 전에 종료
[경계-가시성] 구조는 정상이나 양끝 빈 interval이 없어 이어붙이기 검토 불편
[CSV] 형태소 철자 로마자 열이 없음
[정렬] words 전체가 음성보다 약 0.4초 뒤로 밀림
```

phone이 미세하게 다르다는 관찰을 남길 수는 있지만, 그것을 자동으로 실제
실현 판정이나 사전 오류로 확정하지 않는다.

## 8. 상대 파일 링크 열

네 링크는 모두 같은 Dropbox 평면 폴더를 기준으로 한 파일명만 저장한다.
절대경로를 넣지 않은 이유는 Dropbox 위치가 다른 컴퓨터에서 달라져도
workbook과 파일을 함께 옮기면 링크를 유지하기 위해서다.

### 8.1 `wav_file`

- **출처**: 파일럿 corpus에 사용한 WAV의 SHA 검증 사본
- **역할**: 청취 정본, TextGrid와 함께 Praat에서 열기
- **확인**: 열리는지, 발화 내용·길이가 다른 파일과 일치하는지
- **아님**: 원시 corpus를 수정할 수 있는 작업본

### 8.2 `textgrid_file`

- **출처**: 같은 r2 공통사전·고정 acoustic으로 정렬한 MFA SQLite DB의
  direct 4-tier export
- **역할**: words/phones/morphemes/utterance 구조·경계·대략적 정렬 확인
- **확인**: 같은 WAV와 함께 열리는지, 네 tier가 사용 가능한지
- **아님**: 실제 음운 실현의 정답 annotation

### 8.3 `lab_file`

- **출처**: 동결 검색 CSV의 `pron_reference_form`에서 한글 어절을 뽑아
  MFA에 실제 투입한 전사
- **역할**: MFA가 어떤 입력을 정렬했는지 재현
- **중요**:
  - TextGrid `utterance`는 `form` 출처다.
  - LAB은 `pron_reference_form` 출처다.
  - 둘이 문자 단위로 항상 같아야 하는 것은 아니며, 차이의 출처가
    문서화되고 발화 연결이 맞아야 한다.
- **아님**: 연구자가 들은 실제 발음을 전사한 phone 정답

### 8.4 `csv_file`

- **출처**:
  - `pilot__*`: 표본 선정·입력·화자·경로 정보
  - `search__*`: 동결 pre-MFA search master의 해당 발화 1행
- **역할**: ID·전사·형태소·발음 보조열의 존재와 의미 확인
- **확인**: 향후 전량 검색 CSV/Parquet에 필요한 열과 join key가 갖추어졌는지
- **아님**: 전체 세션 또는 전체 6개년을 검색할 수 있는 단독 파일

## 9. dropdown 허용값과 판정 규칙

### 구성 항목 네 열

대상:
`linkage_status`, `tier_structure_status`, `boundary_status`,
`csv_searchability_status`

| 값 | 의미 |
|---|---|
| `미검토` | 아직 확인하지 않음 |
| `통과` | 현재 인프라 목적에 충분 |
| `문제있음` | 수정 또는 설계 판단이 필요 |
| `해당없음` | 해당 발화에서 평가할 대상이 없음. 남용하지 않고 notes에 이유 권장 |

### 종합 열

| 값 | 의미 |
|---|---|
| `미검토` | 아직 종합하지 않음 |
| `인프라 통과` | 파일·tier·경계·CSV가 후속 연구 흐름에 사용 가능 |
| `수정 후 재검토` | 고친 뒤 같은 기준으로 다시 봐야 함 |

### 자동 validator의 판정

- 모든 60행이 입력돼야 `incomplete`가 아니다.
- `인프라 통과` 행의 구성 열은 모두 `통과` 또는 `해당없음`이어야 한다.
- `수정 후 재검토` 행에는 notes가 필요하다.
- 불변 열이 원본 `REVIEW.csv`와 다르면 검토 내용과 관계없이 실패한다.
- 모든 행이 일관되게 `인프라 통과`일 때만 pilot 연구자 보고서가
  `approved`, `allow_bulk_mfa=true`가 된다.

## 10. 이 검토 결과가 활용되는 곳

### 10.1 즉시 활용

- 60발화 인프라 파일럿 승인 또는 수정 요구 결정
- 연결·tier·경계·CSV 문제의 수정 담당 단계 분류
- 수정 뒤 같은 발화 재검토 목록 생성

### 10.2 전수 MFA 시작 전

- pilot 승인 보고서는 r2 입력·출력 형식이 연구에 사용 가능한지 보여주는
  pre-bulk 근거다.
- 다만 현재 60행 승인만으로 2020–2025 전수 MFA 전체를 무인 승인하지 않는다.
- 최종 코드 commit을 동결하고 2020 전수 실행 후 연도별 QC·표본 연구자
  승인을 다시 수행한다.

### 10.3 전수 연도 전환

- 전수 작업에서는 각 연도별 별도 연구자 표본 보고서를 만든다.
- `preflight_next_year_after_qc.py`는 직전 연도만 포함한 승인 보고서,
  DB 재수출 표본, input/alignment contract가 모두 같은지를 확인한다.
- 현재 6개년 60행 pilot workbook을 2020→2021 전환 보고서로 그대로
  재사용하지 않는다.

### 10.4 최종 연구 인프라

- `utt_id`: 검색 결과와 모든 음성 산출물의 join
- `speaker_id`: 화자별 반복측정·편향 확인
- `session_id`: 대화 맥락·이어붙이기·세션 효과
- CSV 검색성 피드백: 최종 CSV/Parquet 열 설계
- 경계 피드백: 운영 TextGrid와 검토/stitch 사본의 경계 정책 분리
- notes: 방법론 시행착오·품질관리·수정 근거

## 11. 이 표로 결론 내리면 안 되는 것

다음은 별도 연구 단계에서 판단한다.

- ㄴ 삽입, 경음화, 유음화 등 구체적 현상의 실제 실현 여부
- MFA phone과 실제 음성의 완전한 일치
- 우리말샘 발음 또는 규칙 발음 중 어느 것이 이 발화의 실제 정답인지
- wav2vec2 phone의 정확성
- KOINA 운율 분석 결과
- 특정 화자·연도에서의 음운현상 통계

이 정보들은 향후 선택 후보에 별도 열·산출물로 추가하고, 최종 실현 여부는
연구자가 음성과 TextGrid를 보고 판정한다.

## 12. 효율적인 검토 순서

1. 1, 11, 21, 31, 41, 51번으로 연도별 첫 사례를 먼저 본다.
2. 판정 기준이 안정되면 연도당 10행씩 진행한다.
3. 첫 pass에서는 연결·tier 수·경계·CSV 핵심 열만 빠르게 확인한다.
4. `문제있음` 행만 두 번째 pass에서 상세하게 듣고 notes를 쓴다.
5. 연도 하나를 마칠 때마다 저장한다.
6. 파일 이름, 불변 열, 행 수는 바꾸지 않는다.
