# 6개년 인프라 구축 연대기와 주요 결정

이 문서는 채팅 기록을 그대로 재현하는 일지가 아니다. 최종 RC0/RC1과 코드에
영향을 준 사건을 시간 순서로 재구성한 closeout용 방법 연대기다. 수량과 최종
상태는 release manifest가 우선하며, 아래 날짜는 설계가 바뀐 맥락을 설명한다.

## 1. 출발점: CSV와 MFA를 모두 의심하다

초기 문제는 “MFA를 더 빨리 돌리는 법”만이 아니었다. 형태소 CSV가 연구 후보를
정확히 찾을 수 있는지, WAV·전사·화자·세션 identity가 유지되는지, TextGrid가
실제 청취와 수동 판단에 쓸 만한지 확신할 수 없었다. 연구자는 다음 흐름을
명시했다.

1. CSV에서 특정 형태소 또는 표기 환경 후보를 찾는다.
2. 해당 WAV와 TextGrid를 모은다.
3. 선별 자료에 KOINA 등 운율 분석을 적용한다.
4. 연구자가 음성과 TextGrid를 보고 실제 실현 여부를 판단한다.

이때 G2P phone이나 MFA phone을 실제 실현 판정값으로 쓰지 않는다는 원칙이
확정됐다.

## 2. 2026-07-24 전후: 층화 MFA pilot과 첫 fail-closed

처음에는 연도별 소수 발화를 골라 전 과정을 검토했다. 한 화자만 뽑는 실수를
피하기 위해 약 5명 화자와 여러 세션을 포함하도록 표본을 바꿨다. 2023 pilot에서
10개 입력 중 TextGrid가 9개만 생성됐는데도 외형상 작업이 끝난 것처럼 보이는
사건이 있었다. 이후 입력 수와 출력 수가 정확히 같지 않으면 성공으로 처리하지
않는 fail-closed 규칙을 넣었다.

연구자 검토에서는 다음이 발견됐다.

- 검토 목록에는 있으나 corpus·CSV·TextGrid에서 찾지 못하는 ID
- 일부 tier에만 존재하는 앞뒤 빈 구간 경계
- 형태소 tier가 실제 시간 경계처럼 보이지만 다른 tier와 맞지 않는 문제
- 숫자·기호의 철자발음·예측발음이 빈칸인 문제
- 검토할 때 WAV·LAB·TextGrid·CSV를 일일이 찾아야 하는 높은 비용

그 결과 검토 묶음은 연도·번호순으로 필요한 파일을 같이 제공하고, 일부 성공을
자동 통과시키지 않도록 바뀌었다.

## 3. CSV·TextGrid schema 재설계

연구자가 원하는 것은 TextGrid 안에서 모든 형태소를 음성학적으로 강제 분할하는
것이 아니었다. 형태소·표기 환경을 검색하고 해당 음성 위치로 빨리 돌아가는 것이
목적이었다. 따라서 다음 구분을 채택했다.

- CSV/검색층: 세밀한 형태소·POS·어절·기호·철자 로마자 정보
- TextGrid: MFA word/phone 시간과 발화 단위 검색 문자열
- 형태소 tier: 시간 정렬된 형태소 경계가 아니라 발화 범위의 한글 형태소/POS
  문자열

여러 실험적 7-tier 안을 줄여 최종 6-tier를 만들었다. 철자 로마자는 어절
구분자를 보존하고, MFA phone의 넓은 로마자 범주를 `phoneme_r_auto`로 추가했다.
수동 음운전사나 기저형을 자동으로 주장하지 않도록 이름과 설명을 제한했다.

## 4. 공통발음사전: r1/r2 실패에서 r3 계약으로

연도별 inline G2P는 계산 중복뿐 아니라 연도 간 방법론 차이를 만들 수 있었다.
6개년 관측 어휘를 공통 범위로 모아 같은 발음 기준을 적용하는 방향을 채택했다.

초기 r1/r2 과정에서는 다음 문제가 드러났다.

- PowerShell scalar에 `.Count`가 없는 오류
- 음절/grapheme 기준과 동결 음향모델 inventory의 불일치
- Jamo ㄽ 후보 복원 검사의 과도한 중단
- G2P shard에서 입력 1개가 출력되지 않는 no-path
- 같은 실패가 있을 때 장시간 실행 전체가 멈추는 구조
- seed를 UInt32로 바꾸는 과정의 범위 오류

이 과정에서 과거 계산 시간을 보존하려고 기준이 다른 결과를 이어 쓰는 것보다,
최신 Jamo G2P와 동결 모델·사전 hash로 새 계약을 만드는 것이 연구 일관성에 더
적합하다고 판단했다. no-path는 `spn`으로 숨기지 않고 별도 queue로 보존했다.

우리말샘 등 사전 발음은 검색·참조 정보로 가치가 있지만, 사전 변이가 해당
발화의 실제 발음이라는 보장은 없다. A/B 검토에서도 사전 변이가 더 나쁜 사례가
있었다. 따라서 사전 정보는 보조열로 유지하고 MFA 사전에 검토되지 않은 변이를
전부 넣지 않았다.

## 5. 2020–2025 r3 fresh realign 결정

2022 표본의 `있지`, `있는`, `없는`, `어쨌든` 등에서 입력 phone 기준이 의도한
규칙과 맞지 않는 문제가 확인됐다. 이미 끝난 연도의 TextGrid를 사후 문자 교체하면
phone 생성 근거와 시간 정렬 계약이 분리된다. 연구자는 6개년을 같은 r3 기준으로
다시 정렬해 논문 methods에 동일한 기준이라고 쓸 수 있어야 한다고 결정했다.

이때 전체 어휘를 한 번에 확정하지 못한 718,364발화를 안전 본체 밖 발음 후속으로
보존했다. 발화 하나에 hold 어절이 있으면 발화 전체를 보류했기 때문에 수량이
컸다. 이는 삭제가 아니라 보수적인 staged adoption이었다.

## 6. Windows·대량 실행 신뢰성 보강

장시간 실행 중 반복된 운영 문제도 계약에 포함됐다.

- PowerShell 5.1에서 JSON 배열이 단일 `PSCustomObject`로 풀리는 문제
- UTF-8/BOM과 한국어 스크립트 호환
- heartbeat 파일을 모니터와 runner가 동시에 읽고 쓰는 충돌
- gzip CSV 마지막 newline 때문에 expected/actual row가 하나 다른 문제
- 사용자가 프로젝트 root가 아닌 곳에서 상대경로 명령을 실행한 문제
- 실행 창 종료·계정 limit·VS Code 재시작 뒤 상태를 잃는 문제

이에 typed List와 `@(...)` 정규화, heartbeat 비치명화와 FileShare.ReadWrite,
Windows PowerShell 5.1 회귀검사, 절대경로 명령, marker/lock/DB 기반 재개,
`-PreflightOnly`를 표준으로 삼았다. 채팅 상태가 아니라 로컬 checkpoint가 진실의
근거가 되도록 했다.

## 7. 연도별 안전 본체 생산

각 연도는 같은 순서로 처리했다.

```text
검색층/입력 계약
→ pre-MFA exact-ID 기술 제외
→ corpus materialize
→ fresh r3 MFA
→ post-MFA 미정렬 exact-ID 분리와 연구자 승인
→ 보존 DB에서 6-tier 수출
→ 생성기와 독립된 QC
→ 다음 연도 Gate
```

2020의 WAV ID recovery, 2021의 0.0 duration과 heartbeat 충돌, 2022의 잡음·겹침
검토, 2023의 대규모 audio pairing unresolved, 2024의 gzip row mismatch와 export
실패/성공 보고서 공존, 2025의 post-MFA 미정렬이 각각 별도 증거로 남았다.

중요한 변화는 오류가 날 때 완료된 연도나 연도 전체를 다시 시작하지 않았다는
점이다. 성공 DB와 checkpoint를 보존하고 문제가 있는 exact-ID만 후속으로 넘겼다.

## 8. 연구 DB v1 RC0: 전 발화 상태 회계

6개년 MFA 뒤에는 강제정렬 성공 파일만 세는 대신 원천 5,103,356발화가 어디에
있는지 완전 회계했다. 결과는 다음과 같다.

```text
5,103,356
= 4,286,046 aligned_safe_body
+    95,860 pre_mfa_technical_exclusion
+     3,086 post_mfa_technical_exclusion
+   718,364 pronunciation_followup
+         0 methodological_exclusion
```

이 회계 덕분에 검색 분모와 TextGrid 분모가 다른 이유를 설명할 수 있고, 기술
실패가 조용히 사라지지 않는다. 같은 발음 release·사전·모델·runtime·schema가
6개년에 적용됐는지도 교차 감사했다.

## 9. recovery D0–D10과 RC1

후속 817,310건을 43개 reason routing unit으로 나누고, 첫 55건 진단 shard를
다뤘다. 매우 짧은 음원은 같은 입력으로 반복하지 않았고, MFA 미정렬 19건만
격리 namespace에서 beam 100/retry 400으로 한 차례 재시도했다.

연구자 청취 결과는 다음과 같이 세분됐다.

- 자동 결과를 직접 채택할 수 있는 소수
- 음성은 유효하지만 전사·word 경계를 수동 수정할 항목
- 부분 정렬을 증거로 보존할 항목
- 잡음·겹침·음질 문제로 기술 제외할 항목

수동 TextGrid 16건은 D10 반환본으로 동결했다. 하지만 수정 전사에 맞는 형태소와
phone/phoneme을 아직 다시 만들지 않았기 때문에 기존 자동층을 최종값으로
소급하지 않았다. RC1은 RC0 위에 55행 상태와 16행 pointer를 붙이는 sidecar로
채택됐고 본체 정렬 수는 바뀌지 않았다.

## 10. active view와 실제 연구로의 연결

RC0 기본값과 RC1 exact-ID 예외를 하나의 논리적 view로 읽는 계약을 만들었다.
그 위에서 형태소·표기 환경 후보 22 occurrence를 만들고, 실제 환경 후보 20건 중
TextGrid가 있는 19건을 `words` interval 문맥과 연결했다. 이 시간은 연구자가
들을 어절 문맥이며 실제 음운 경계가 아니다.

ㄴ 삽입 B1에서는 과거의 “MFA phone을 실현 판정으로 사용”하는 잘못된 표현을
폐기했다. 어절 내부/어절 간 환경을 분리하고, J*/E* 및 숫자·기호 인접을 제외하며,
실현은 연구자가 수동 판정한다. 이 규칙은 승인됐지만 6개년 production query와
의미번호 join은 closeout 이후의 연구 단계로 남아 있다.

## 11. 2026-08-18 closeout의 결론

완료된 것은 6개년 전체를 검색할 수 있는 형태소·표기 인프라, 동일 r3 계약의
428만 6-tier, 510만 exact-ID 상태 회계, 81만 후속의 회수 경로, 수동 보정
sidecar와 후보 연결 인프라다.

완료되지 않은 것은 개별 음운 현상의 전수 후보 추출, 실제 실현 판정, KOINA,
보조 음성모델 전수 적용과 81만 후속의 완전 회수다. 그러므로 이 단계는 충분히
독립적인 자료 구축 산출물이지만 음운 연구 결과로 제시해서는 안 된다.
